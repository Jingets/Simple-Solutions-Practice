**R-001 Структура репозитория**

**Статус:** MVP

**Приоритет:** P0

**Цель**

Настоящий документ определяет единую структуру репозитория платформы Simple Solutions Practice.

Все исходные коды, конфигурационные файлы, документация и ресурсы проекта должны размещаться исключительно в соответствии с настоящим документом.

**Структура модуля**

Каждый модуль должен иметь одинаковую структуру.

Допускается расширение структуры только при необходимости.

**Artifacts**

Каталог предназначен для хранения файлов проектов.

Физическое размещение Artifact определяется конфигурацией платформы.

Программный код не должен обращаться к Artifact напрямую.

Доступ осуществляется исключительно через Artifact Manager.

tests/

Каждый бизнес-модуль обязан иметь собственный набор тестов.

**Правила именования**

Имена каталогов:

- только lowercase;

- snake\_case;

- без пробелов;

- без специальных символов.

Имена Python-модулей:

- snake\_case.

Имена классов:

- PascalCase.

Имена API Endpoint:

- REST-style.

**Архитектурные ограничения**

Запрещается:

- размещать бизнес-логику в Platform Kernel;

- обращаться к базе данных напрямую из Frontend;

- создавать прямые зависимости между бизнес-модулями;

- использовать общие глобальные переменные;

- размещать временные файлы внутри исходного кода.

**Правило модульности**

Каждый бизнес-модуль должен иметь возможность разрабатываться, тестироваться и сопровождаться независимо от остальных модулей.

Замена внутренней реализации модуля не должна требовать изменения остальных компонентов платформы при сохранении публичного контракта модуля.

**Definition of Done**

Структура репозитория считается утверждённой, если:

- все каталоги имеют однозначное назначение;

- каждый модуль имеет стандартную структуру;

- отсутствуют циклические зависимости;

- Platform Kernel полностью отделён от бизнес-модулей;

- структура допускает расширение без изменения существующих компонентов.

**Результат**

После утверждения настоящего документа разработчики и среды вайб-кодинга получают единые правила организации репозитория, обеспечивающие предсказуемую структуру проекта, независимость модулей и возможность дальнейшего масштабирования платформы.
