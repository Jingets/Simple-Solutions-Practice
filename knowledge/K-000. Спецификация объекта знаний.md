# K-000. Спецификация объекта знаний

## Назначение

Объект знаний (Knowledge Object, KO) является минимальной неделимой единицей экспертных знаний платформы SSP.

Все рекомендации, диагностические отчёты, коммерческие предложения, дорожные карты, сертификаты и другие документы формируются системой на основе объектов знаний.

Объекты знаний являются единственным источником экспертных знаний платформы.

---

# Основные принципы

Каждый объект знаний обязан:

* описывать только одну бизнес-проблему;
* содержать только проверенные экспертные знания;
* быть независимым от формата представления информации;
* использоваться повторно в различных сервисах платформы;
* поддерживать версионирование.

Объект знаний не должен содержать оформление документа.

За оформление отвечают шаблоны документов.

---

# Формат хранения

Каждый объект знаний хранится в отдельном YAML-файле.

Пример:

```text
knowledge/objects/revenue/KB-REV-001.yaml
```

---

# Правила именования

Идентификатор объекта знаний имеет формат:

```text
KB-<CATEGORY>-XXX
```

Примеры:

```text
KB-REV-001
KB-SALES-004
KB-OPS-017
KB-MKT-009
```

Идентификатор никогда не изменяется.

---

# Структура объекта знаний

Каждый объект знаний обязан содержать следующие поля.

```yaml
id:

title:

category:

subcategory:

symptoms:

possible_causes:

required_evidence:

diagnostic_questions:

business_rules:

recommended_actions:

expected_effect:

related_objects:

tags:

applicable_industries:

company_size:

complexity:

confidence:

version:

created:

updated:
```

Все поля являются обязательными.

Если значение отсутствует, используется пустая коллекция или значение `null`.

---

# Правила наполнения

Каждый объект знаний описывает только одну бизнес-ситуацию.

Несколько независимых проблем не должны объединяться в одном объекте знаний.

Для каждой самостоятельной проблемы создаётся отдельный объект знаний.

---

# Рекомендуемые действия

Поле `recommended_actions` должно содержать конкретные исполнимые действия.

Корректные примеры:

* Провести аудит ценообразования.
* Выполнить ABC-анализ клиентов.
* Проанализировать повторные продажи.

Некорректные примеры:

* Улучшить бизнес.
* Работать эффективнее.
* Повысить качество управления.

---

# Бизнес-правила

Поле `business_rules` содержит экспертную логику платформы.

Бизнес-правила не являются мнением консультанта.

Бизнес-правила могут ссылаться на другие объекты знаний.

---

# Связи между объектами

Объекты знаний могут ссылаться друг на друга через поле `related_objects`.

Связи являются направленными.

По возможности следует избегать циклических зависимостей.

---

# Версионирование

Экспертные знания развиваются со временем.

Идентификатор объекта знаний остаётся неизменным.

При изменении содержания изменяется только номер версии.

---

# Правила изменения

Объект знаний изменяется только в случаях:

* появления новых экспертных знаний;
* накопления подтверждённой практики;
* исправления ошибок.

Объекты знаний не изменяются для компенсации недостатков программной реализации.

---

# Разделение ответственности

Объекты знаний содержат экспертные знания.

Шаблоны документов отвечают за оформление.

Программный код отвечает за обработку и генерацию документов.

Эти обязанности не должны пересекаться.

---

# Правило развития

База знаний развивается только на основании реальных консультационных проектов.

Каждое изменение должно подтверждаться практикой, а не предположениями.

Структура объектов знаний должна оставаться совместимой между версиями платформы.
