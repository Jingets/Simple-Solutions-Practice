# DOCUMENT STANDARD

## Назначение

Настоящий документ определяет единый стандарт создания, хранения, генерации и жизненного цикла документов платформы **Simple Solutions Practice (SSP)**.

Все документы платформы обязаны соответствовать требованиям настоящего стандарта.

---

# Основные принципы

Каждый документ платформы является самостоятельным бизнес-объектом.

Документ не существует отдельно от проекта и создаётся автоматически платформой.

Главной сущностью платформы является **Проект (Project)**.

Все документы относятся к одному проекту.

---

# Идентификаторы

Каждый проект получает уникальный идентификатор.

Пример:

```text
PRJ-000127
```

Все документы проекта используют данный идентификатор как основной ключ связи.

---

# Типы документов

Платформа использует следующие типы документов.

| Код | Документ                 |
| --- | ------------------------ |
| OFR | Offer (Договор-оферта)   |
| INV | Invoice (Счёт на оплату) |
| ACT | Акт выполненных работ    |
| REP | Итоговый отчёт           |
| CRT | Сертификат               |

---

# Нумерация документов

Каждый документ получает собственный номер.

Пример:

```text
PRJ-000127

↓

OFR-000127

INV-000127

ACT-000127

REP-000127

CRT-000127
```

Номер документа совпадает с номером проекта.

При необходимости допускается создание нескольких документов одного типа.

Пример:

```text
INV-000127-01

INV-000127-02
```

---

# Структура документа

Каждый документ платформы состоит из трёх файлов.

## 1. Documentation

Файл

```text
XXX.md
```

Содержит описание документа.

Используется людьми.

---

## 2. Machine Specification

Файл

```text
XXX.yaml
```

Содержит машинное описание документа.

Используется Backend, Frontend и AI.

---

## 3. Rendering Template

Файл

```text
XXX.template.md
```

Содержит шаблон документа.

Используется системой генерации PDF и DOCX.

---

# Канонический источник данных

YAML является единственным каноническим источником структурированных данных.

Шаблон документа не содержит бизнес-логики.

Все значения автоматически подставляются системой из объектов проекта.

---

# Обязательные поля YAML

Каждый YAML-документ обязан содержать следующие поля.

```yaml
id:

title:

version:

document_type:

generated:

project_id:

template:

status:
```

Дополнительные поля определяются конкретным типом документа.

---

# Жизненный цикл документа

Документ проходит следующие стадии.

```text
Template

↓

Generated

↓

Published

↓

Archived
```

Редактирование опубликованных документов не допускается.

При изменении данных проекта документ формируется повторно с новой версией.

---

# Связь документов

Все документы проекта связаны между собой посредством идентификатора проекта.

```text
PRJ

↓

OFR

↓

INV

↓

ACT

↓

REP

↓

CRT
```

Документы не должны содержать прямых ссылок друг на друга.

Связь осуществляется исключительно через Project.

---

# Генерация документов

Документы создаются платформой автоматически.

Backend использует YAML как источник данных.

Rendering Engine использует соответствующий шаблон.

Frontend отображает сформированные документы пользователю.

---

# Правила хранения

Каждый документ хранится:

* в базе данных;
* в рабочем пространстве проекта;
* в формате PDF;
* при необходимости — в формате DOCX.

---

# Архитектурный принцип

Документы платформы являются частью единой модели данных SSP.

Изменение структуры документа допускается только посредством изменения настоящего стандарта либо соответствующего YAML-описания.

Ручное изменение сформированных документов не допускается.
