# DOCUMENT STANDARD

## Назначение

Настоящий документ определяет единый стандарт создания, хранения, генерации и жизненного цикла документов платформы **Simple Solutions Practice (SSP)**.

Все документы платформы обязаны соответствовать требованиям настоящего стандарта.

---

# Основные принципы

Каждый документ платформы является самостоятельным бизнес-объектом.

Документ не существует отдельно от проекта и создаётся автоматически платформой.

Главной сущностью платформы является **Проект (Project)**.

Все документы относятся к одному проекту.

---

# Идентификаторы

Каждый проект получает уникальный идентификатор.

Пример:

```text
PRJ-000127
```

Все документы проекта используют данный идентификатор как основной ключ связи.

---

# Типы документов

Платформа использует следующие типы документов.

| Код | Документ                 |
| --- | ------------------------ |
| OFR | Offer (Договор-оферта)   |
| INV | Invoice (Счёт на оплату) |
| ACT | Акт выполненных работ    |
| REP | Итоговый отчёт           |
| CRT | Сертификат               |

---

# Нумерация документов

Каждый документ получает собственный номер.

Пример:

```text
PRJ-000127

↓

OFR-000127

INV-000127

ACT-000127

REP-000127

CRT-000127
```

Номер документа совпадает с номером проекта.

При необходимости допускается создание нескольких документов одного типа.

Пример:

```text
INV-000127-01

INV-000127-02
```

---

# Структура документа

Каждый документ платформы состоит из трёх файлов.

## 1. Documentation

Файл

```text
XXX.md
```

Содержит описание документа.

Используется людьми.

---

## 2. Machine Specification

Каждый автоматически формируемый документ платформы содержит файл машинного описания.

Файл имеет формат YAML и является единственным каноническим источником информации для Backend, Frontend и AI-агентов.

Файл описывает не содержимое документа, а правила его генерации.

---

# Единая структура YAML

Все документы платформы используют одинаковую структуру.

```yaml
id:

title:

version:

document_type:

status:

template:

description:

inputs:

sources:

generation:

outputs:

business_events:

storage:

editable:

language:
```

Дополнительные поля допускаются только при необходимости конкретного типа документа.

---

# Описание полей

## id

Краткий код типа документа.

Примеры:

* OFR
* INV
* ACT
* REP
* CRT

---

## title

Человекочитаемое название документа.

---

## version

Версия структуры документа.

---

## document_type

Тип документа.

Используется системой генерации документов.

---

## status

Текущий статус шаблона.

Допустимые значения:

* active
* archived

---

## template

Имя файла шаблона, используемого Rendering Engine.

---

## description

Краткое описание назначения документа.

---

## inputs

Перечень бизнес-объектов, необходимых для генерации документа.

Пример:

```yaml
inputs:

  - project

  - contractor

  - client

  - service
```

---

## sources

Документы платформы, являющиеся источниками информации.

Пример:

```yaml
sources:

  - SRV-001

  - PRC-001
```

---

## generation

Описание момента создания документа.

Пример:

```yaml
generation:

  trigger: OfferGenerated
```

---

## outputs

Перечень результатов генерации.

Например:

```yaml
outputs:

  - pdf
```

В дальнейшем допускается расширение:

* docx
* html
* json

---

## business_events

Business Events, связанные с данным документом.

Пример:

```yaml
business_events:

  created: InvoiceGenerated

  paid: PaymentReceived
```

Документ не инициирует бизнес-логику самостоятельно.

Он лишь фиксирует регистрацию соответствующих событий.

---

## storage

Описание места хранения документа.

Пример:

```yaml
storage:

  workspace: true

  database: true
```

---

## editable

Признак возможности ручного изменения сформированного документа.

Для документов MVP используется значение:

```yaml
editable: false
```

---

## language

Язык автоматически формируемого документа.

Для MVP:

```yaml
language: ru-RU
```

---

# Архитектурный принцип

Все автоматически формируемые документы SSP используют одинаковую структуру YAML.

Backend, Frontend и AI-агенты не должны содержать специальных правил обработки отдельных типов документов.

Любой новый документ платформы обязан соответствовать настоящему стандарту.

---

## 3. Rendering Template

Файл

```text
XXX.template.md
```

Содержит шаблон документа.

Используется системой генерации PDF и DOCX.

---

# Канонический источник данных

YAML является единственным каноническим источником структурированных данных.

Шаблон документа не содержит бизнес-логики.

Все значения автоматически подставляются системой из объектов проекта.

---

# Обязательные поля YAML

Каждый YAML-документ обязан содержать следующие поля.

```yaml
id:

title:

version:

document_type:

generated:

project_id:

template:

status:
```

Дополнительные поля определяются конкретным типом документа.

---

# Жизненный цикл документа

Документ проходит следующие стадии.

```text
Template

↓

Generated

↓

Published

↓

Archived
```

Редактирование опубликованных документов не допускается.

При изменении данных проекта документ формируется повторно с новой версией.

---

# Связь документов

Все документы проекта связаны между собой посредством идентификатора проекта.

```text
PRJ

↓

OFR

↓

INV

↓

ACT

↓

REP

↓

CRT
```

Документы не должны содержать прямых ссылок друг на друга.

Связь осуществляется исключительно через Project.

---

# Генерация документов

Документы создаются платформой автоматически.

Backend использует YAML как источник данных.

Rendering Engine использует соответствующий шаблон.

Frontend отображает сформированные документы пользователю.

---

# Правила хранения

Каждый документ хранится:

* в базе данных;
* в рабочем пространстве проекта;
* в формате PDF;
* при необходимости — в формате DOCX.

---

# Архитектурный принцип

Документы платформы являются частью единой модели данных SSP.

Изменение структуры документа допускается только посредством изменения настоящего стандарта либо соответствующего YAML-описания.

Ручное изменение сформированных документов не допускается.
