# Reports Knowledge Base

## Назначение

Раздел **reports** является единым источником информации о результатах консультационных услуг платформы **Simple Solutions Practice (SSP)**.

Все итоговые аналитические документы формируются исключительно на основании стандартов, определённых в настоящем разделе.

---

# Состав раздела

Раздел содержит описание итогового аналитического отчёта SSP и правила его автоматической генерации.

## REP

Итоговый аналитический отчёт.

Определяет:

* структуру отчёта;
* обязательные разделы;
* правила формирования выводов;
* правила подготовки рекомендаций;
* машинную спецификацию отчёта;
* шаблон генерации.

# Принцип работы

Каждый завершённый проект SSP обязан завершаться формированием итогового аналитического отчёта.

Структура отчёта определяется платформой и одинакова для всех проектов.

Конкретное содержание отчёта формируется консультантом на основании проведённой диагностики.

---

# Методология подготовки отчёта

Итоговый аналитический отчёт SSP строится по принципу последовательного анализа причинно-следственных связей.

Основой отчёта являются фактические данные, предоставленные Заказчиком и полученные в ходе исследования.

На основании исходных данных выполняется аналитическая обработка информации.

Результатом анализа является выявление проблем и определение причин их возникновения.

Рекомендации являются следствием проведённого анализа и должны иметь логическое обоснование.

---

# Принцип трассируемости рекомендаций

Каждая рекомендация должна иметь подтверждение в материалах исследования.

Последовательность формирования выводов является обязательной.

```text
Исходные данные

↓

Анализ

↓

Выявленные проблемы

↓

Причины возникновения

↓

Рекомендации

↓

План первоочередных действий
```

Нарушение данной последовательности не допускается.

---

# Правила подготовки рекомендаций

Каждая рекомендация должна:

* опираться на результаты анализа;
* ссылаться на конкретную выявленную проблему;
* устранять выявленную причину;
* содержать практическое действие;
* описывать ожидаемый эффект внедрения.

Рекомендации, не имеющие подтверждения в результатах анализа, не допускаются.

---

# Структура итогового отчёта

Каждый отчёт SSP должен содержать следующие разделы:

1. Паспорт проекта.
2. Цель исследования.
3. Исходные данные.
4. Анализ.
5. Выявленные проблемы.
6. Причины возникновения.
7. Рекомендации.
8. План первоочередных действий.
9. Заключение.

Изменение порядка разделов не допускается.

# Архитектурный принцип

Аналитический отчёт SSP представляет собой причинно-следственную модель исследуемого бизнеса.

Каждый вывод должен быть проверяем.

Каждая рекомендация должна быть обоснована.

Отчёт должен позволять проследить путь от любого исходного факта до любой сформулированной рекомендации.

Редактирование структуры отчёта выполняется только посредством изменения файлов настоящего раздела.

Изменение программного кода платформы не требуется.
