**S-004 Стандарты тестирования**

**Статус:** MVP

**Приоритет:** P0

**Цель**

Настоящий документ определяет единый стандарт тестирования платформы Simple Solutions Practice.

Каждый программный компонент платформы должен сопровождаться тестами, подтверждающими корректность его работы.

Тестирование является обязательной частью разработки.

**Основной принцип**

Непротестированный функционал считается нереализованным.

Каждый завершённый модуль должен иметь набор тестов, подтверждающих выполнение заявленной бизнес-функции.

**Уровни тестирования**

Платформа использует четыре уровня тестирования.

**Unit Testing**

Проверяет отдельные функции, классы и сервисы.

Unit Test не обращается:

- к базе данных;

- к сети;

- к файловой системе;

- к внешним API.

Unit Test выполняется изолированно.

**Integration Testing**

Проверяет взаимодействие компонентов.

Минимально проверяются:

- Repository;

- Database;

- API;

- Artifact Manager;

- Workflow Engine.

**Module Testing**

Проверяет работу модуля как законченной бизнес-функции.

Каждый модуль обязан иметь сценарий успешного выполнения.

Минимально проверяется:

- регистрация Capability;

- регистрация Events;

- создание Artifact;

- корректное завершение Workflow.

**System Testing**

Проверяет полный бизнес-процесс.

Минимально тестируется полный цикл MVP:

Lead

↓

Check-up

↓

Offer Contract

↓

Project Execution

↓

Acceptance Certificate

↓

Organizational Memory

**Обязательные проверки**

Каждый модуль обязан проходить:

**Регистрация**

Проверяется успешная регистрация в Platform Kernel.

**Capability**

Все зарегистрированные Capability должны успешно вызываться.

**Events**

Проверяется публикация всех Business Event.

**Artifact**

Проверяется создание Artifact.

**Workflow**

Проверяется изменение состояния Workflow.

**Error Handling**

Проверяется корректная обработка ошибок.

**Отрицательные сценарии**

Для каждого модуля должны существовать тесты ошибочных ситуаций.

Минимально:

- отсутствие обязательных данных;

- нарушение Platform Policy;

- невозможность регистрации;

- ошибка Repository;

- ошибка Workflow.

**Повторяемость**

Все тесты должны выполняться независимо.

Результат тестов не должен зависеть:

- от порядка выполнения;

- от ранее выполненных тестов;

- от состояния среды.

**Данные тестирования**

Тестовые данные создаются автоматически.

Использование рабочих данных запрещено.

**Автоматизация**

Все тесты должны запускаться автоматически.

Ручная проверка не считается тестированием.

**Производительность**

Тесты должны быть быстрыми.

Unit Test не должен обращаться к внешним ресурсам.

Integration Test использует только тестовую инфраструктуру.

**Покрытие**

Для MVP обязательным является покрытие:

- Platform Kernel;

- всех Capability;

- всех Workflow;

- всех Business Event;

- всех Repository;

- всех публичных API.

Абсолютное процентное покрытие кода не является целью.

Приоритетом является покрытие бизнес-сценариев.

**Запрещается**

Запрещается:

- пропускать тестирование новых модулей;

- изменять тесты для сокрытия ошибок;

- использовать тесты как средство изменения бизнес-логики;

- создавать тесты, зависящие друг от друга.

**Definition of Done**

Модуль считается завершённым только при выполнении следующих условий:

- успешно проходит Unit Testing;

- успешно проходит Integration Testing;

- успешно проходит Module Testing;

- не нарушает существующие System Test;

- не создаёт регрессий в Platform Kernel;

- проходит автоматическую проверку без ручного вмешательства.

**Главный принцип**

Тестирование подтверждает корректность реализации бизнес-функции, а не количество написанного программного кода.

Работающим считается только тот модуль, который успешно проходит полный цикл автоматизированной проверки.
