**S-002 Стандарты API**

**Статус:** MVP

**Приоритет:** P0

**Цель**

Настоящий документ определяет единый стандарт проектирования API платформы Simple Solutions Practice.

Все HTTP API платформы должны соответствовать настоящему стандарту.

Настоящий документ обязателен для всех бизнес-модулей платформы.

**Основной принцип**

API является публичным контрактом платформы.

После публикации изменение контракта допускается только через версионирование.

Внутренняя реализация модуля не влияет на API.

**Архитектура**

Используется REST API.

Все запросы проходят исключительно через Backend.

Frontend не имеет прямого доступа к базе данных.

**Версионирование**

Все Endpoint обязаны иметь версию.

Пример:

/api/v1/

**Формат данных**

Все запросы и ответы используют JSON.

Использование XML запрещено.

**Кодировка**

UTF-8.

**Именование Endpoint**

Используются существительные.

Допускаются только lowercase.

Используется kebab-case.

Примеры

/api/v1/projects

/api/v1/checkups

/api/v1/contracts

**HTTP Methods**

Используются только стандартные методы.

GET

Получение данных.

POST

Создание объекта.

PUT

Полное изменение объекта.

PATCH

Частичное изменение.

DELETE

Удаление (если допускается Platform Policy).

**URI**

URI должен описывать ресурс.

Пример

GET

/projects/{project\_id}

Не допускается

/getProject

**Ответ API**

Все успешные ответы используют единый формат.

{

"success": true,

"data": {},

"meta": {}

}

**Ошибки**

Все ошибки используют единый формат.

{

"success": false,

"error": {

"code": "",

"message": "",

"details": {}

}

}

**HTTP Status**

Используются только стандартные коды.

200

201

204

400

401

403

404

409

422

500

Использование нестандартных кодов запрещено.

**Pagination**

Все списки поддерживают постраничную выдачу.

Минимальные параметры:

page

page\_size

**Sorting**

Поддерживается параметр

sort

**Filtering**

Фильтрация выполняется исключительно через Query Parameters.

**Идентификаторы**

Все бизнес-объекты используют UUID.

Последовательные числовые идентификаторы запрещены.

**Дата и время**

Используется ISO-8601.

UTC является внутренним стандартом хранения.

**Валидация**

Все входящие данные валидируются через Pydantic.

Невалидные данные не передаются в бизнес-логику.

**Документирование**

Каждый Endpoint обязан автоматически публиковаться в OpenAPI.

Swagger генерируется автоматически.

**Идемпотентность**

GET

PUT

DELETE

должны быть идемпотентными.

POST допускает создание нового объекта.

**Архитектурные ограничения**

API не содержит бизнес-логики.

API:

- принимает запрос;

- валидирует данные;

- вызывает Capability соответствующего модуля;

- возвращает результат.

**Definition of Done**

Endpoint считается соответствующим стандарту, если:

- использует REST;

- имеет версию;

- документируется через OpenAPI;

- использует единый формат ответа;

- использует единый формат ошибок;

- проходит автоматическую валидацию;

- не содержит бизнес-логики.

**Главный принцип**

API описывает возможности платформы, а не внутреннюю реализацию модулей.

Изменение внутреннего устройства платформы не должно приводить к изменению опубликованного API.
