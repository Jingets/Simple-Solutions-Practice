**M-101 Ядро системы**

**Статус:** MVP

**Приоритет:** P0 (обязательный)

**Цель**

Реализовать минимальное ядро платформы SSP, обеспечивающее выполнение бизнес-процессов первого коммерческого MVP.

После выполнения задания платформа должна быть способна зарегистрировать модули, выполнить Workflow и сохранить результаты работы.

**Контекст**

Platform Kernel является единственной точкой управления платформой.

Все остальные компоненты взаимодействуют исключительно через Kernel.

Kernel не содержит бизнес-логики.

Kernel отвечает только за оркестрацию.

**Необходимо реализовать**

**Module Registry**

Kernel должен:

- регистрировать модули при запуске;

- хранить список активных модулей;

- предоставлять информацию о зарегистрированных Capability.

**Capability Registry**

Kernel должен:

- регистрировать Capability;

- выполнять поиск Capability;

- вызывать Capability по идентификатору.

**Workflow Engine**

Kernel должен:

- запускать Workflow;

- выполнять последовательность Capability;

- передавать Module Context;

- получать Capability Result.

**Типы шагов Workflow в MVP:**

**LINEAR** — последовательное выполнение Capability друг за другом;

**CONDITIONAL** — выбор следующего шага на основе результата предыдущей Capability (ветвление);

**RETRY** — возврат к предыдущему шагу (используется, например, при необходимости пересмотра коммерческого предложения).

Управление переходом между шагами осуществляется через поле next_step в результате выполнения Capability. Workflow Engine не содержит бизнес-логики принятия решений — только исполняет указанный разработчиком маршрут.

**Event Engine**

Kernel должен:

- регистрировать Business Event;

- регистрировать System Event.

**Artifact Storage**

Kernel должен:

- принимать Artifact;

- сохранять Artifact;

- возвращать Artifact по идентификатору.

Любой Artifact в MVP имеет статусы: DRAFT (редактируется) и PUBLISHED (утверждён консультантом и доступен другим модулям). Переход статуса возможен только явным действием консультанта.

**Не реализовывать**

Не входят в первую версию:

- Security & Identity (базовая аутентификация консультанта реализуется отдельным минимальным модулем).

- AI;

- Marketplace;

- Plugin Store;

- Domain Federation;

- SDK Generator;

- API LLM;

- Manifest Generator;

- Event Bus;

- распределённое выполнение;

- масштабирование.

**Архитектурные ограничения**

Kernel:

- не содержит бизнес-логики;

- не знает предметную область;

- не принимает управленческих решений;

- не хранит состояние бизнес-процессов;

- только координирует выполнение.

**Definition of Done**

Kernel считается готовым, если:

- модуль успешно регистрируется;

- Capability успешно регистрируется;

- Workflow выполняется;

- Business Event создаётся;

- Artifact сохраняется;

- результат возвращается вызывающему модулю.

**Результат**

После выполнения задания платформа получает первую работоспособную инфраструктуру выполнения бизнес-процессов.
