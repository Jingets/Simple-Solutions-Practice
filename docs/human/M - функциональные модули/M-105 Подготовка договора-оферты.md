# M-105. Подготовка договора-оферты

## 1. Назначение

Модуль обеспечивает подготовку, генерацию, публикацию и сопровождение договора-оферты в рамках Pilot MVP.

Договор-оферта является юридическим предложением заключить договор на оказание консультационных услуг.

После принятия оферты создаётся событие `OfferAccepted`, которое инициирует переход Project в состояние `IN_PROGRESS`.

---

# 2. Цель модуля

Модуль должен обеспечивать:

- подготовку оферты на основании результатов диагностики;
- автоматическое заполнение реквизитов;
- генерацию документа;
- регистрацию публикации;
- генерацию счёта;
- фиксацию принятия оферты;
- запуск проекта.

---

# 3. Входные данные

Для подготовки оферты используются:

- Project;
- Customer;
- Estimation Report;
- выбранный Service;
- Platform Legal Profile;
- стоимость работ;
- срок выполнения;
- условия оплаты.

Все данные должны существовать до начала генерации документа.

---

# 4. Выходные данные

Результатом являются:

- Offer Contract (Artifact);
- Invoice (Artifact);
- Business Event `OfferPublished`;
- Business Event `InvoiceGenerated`.

После регистрации оплаты создаётся:

```
PaymentRegistered
```

После подтверждения принятия оферты:

```
OfferAccepted
```

---

# 5. Бизнес-правила

Оферта может быть подготовлена только если:

- существует Project;
- завершён Check-up;
- существует Estimation Report;
- определён Customer;
- определён Platform Legal Profile;
- определён Service;
- стоимость согласована.

Повторная публикация оферты допускается только как новая версия.

---

# 6. Источники данных

| Поле | Источник |
|------|----------|
| Номер договора | Platform Kernel |
| Дата | System Clock |
| Customer | Customer |
| Исполнитель | Platform Legal Profile |
| Услуга | Service |
| Стоимость | Estimation Report |
| Срок | Estimation Report |
| Основание | Project |
| Проект | Project |

---

# 7. Генерация документа

Генерация выполняется из:

```
knowledge/documents/offer-contract.yaml
knowledge/templates/offer-contract.template.md
```

Шаблон обязан соответствовать `knowledge/document-standard.md`.

Все переменные шаблона должны иметь определённый источник данных.

---

# 8. Invoice

После публикации оферты автоматически создаётся Invoice.

Источник данных:

- Offer Contract;
- Platform Legal Profile;
- Customer;
- сумма;
- назначение платежа.

Invoice является самостоятельным Artifact.

---

# 9. Жизненный цикл

```text
DRAFT
→ GENERATED
→ PUBLISHED
→ ACCEPTED
→ ARCHIVED
```

Описание состояний:

| Статус | Назначение |
|--------|------------|
| DRAFT | подготовка данных |
| GENERATED | документ сформирован |
| PUBLISHED | отправлен заказчику |
| ACCEPTED | оферта принята |
| ARCHIVED | устаревшая версия |

Project не меняет своё состояние при публикации оферты.

---

# 10. События

При генерации используются:

```
OfferPublished
InvoiceGenerated
PaymentRegistered
OfferAccepted
```

Только событие `OfferAccepted` изменяет состояние Project.

---

# 11. API

Минимальный набор endpoints:

```
POST /offers
GET /offers/{id}
POST /offers/{id}/publish
POST /offers/{id}/accept

GET /invoices/{id}
POST /invoices/{id}/register-payment
```

Все операции используют единый API Contract.

---

# 12. Проверки

Перед публикацией проверяется:

- заполнены обязательные реквизиты;
- существует Customer;
- существует Service;
- существует Platform Legal Profile;
- существует Estimation Report;
- сумма больше нуля;
- существует шаблон;
- существует YAML;
- существуют все источники данных.

---

# 13. Ошибки

Минимальный набор кодов ошибок:

```
OFFER_TEMPLATE_NOT_FOUND
OFFER_SOURCE_DATA_MISSING
OFFER_ALREADY_PUBLISHED
PAYMENT_ALREADY_REGISTERED
PROJECT_INVALID_STATE
```

Используется единый Error Contract.

---

# 14. Идемпотентность

Идемпотентными являются:

- публикация оферты;
- регистрация оплаты;
- принятие оферты.

Используется:

```
Idempotency-Key
```

Повторный запрос с тем же ключом возвращает ранее полученный результат.

---

# 15. Acceptance Criteria

Модуль считается завершённым, если:

- генерируется Offer Contract;
- генерируется Invoice;
- документы сохраняются как Artifact;
- создаются Business Events;
- после `OfferAccepted` Project переходит в `IN_PROGRESS`;
- повторная публикация создаёт новую версию;
- повторный вызов идемпотентной операции не изменяет состояние повторно;
- integration и E2E tests проходят.

---

---

# 17. Не входит в Pilot MVP

Не реализуются:

- электронная подпись;
- квалифицированная ЭП;
- интеграция с ЭДО;
- автоматическая отправка электронной почтой;
- онлайн-эквайринг;
- интеграция с банками;
- юридическое согласование нескольких редакций;
- маршруты согласования документа.
