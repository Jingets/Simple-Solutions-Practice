**M-001. Дорожная карта разработки MVP**

**Назначение**

Настоящий документ определяет состав, границы и последовательность
разработки первой рабочей версии SSP (Minimum Viable Product).

Цель MVP — подтвердить работоспособность архитектуры платформы на одном
полностью завершённом консультационном процессе.

Первая версия платформы не предназначена для масштабирования,
автоматизации или поддержки нескольких пользователей.

**Цель MVP**

Первая версия SSP должна обеспечивать выполнение полного
консультационного цикла от регистрации первичного обращения до выдачи
итоговой результативной документации, включая подготовку коммерческого предложения (Proposal), заключение договора-оферты, выполнение работ и оформление акта. 


Результатом разработки является работающая система, позволяющая
выполнить один завершённый консультационный проект.

**Сквозной Workflow**

В MVP реализуется сквозной Workflow: LeadRegistration → CheckupCompletion → EstimationPublication → OfferPublication → OfferAcceptance → ProjectExecution → ProjectCompletion → ProjectClosure

**Границы MVP**

В состав MVP входит исключительно следующий бизнес-процесс:

Lead → Check-up → Estimation → Offer → Workspace → Execution → Certificate

Каждый этап должен быть полностью реализован и работоспособен.

Частично реализованные процессы не входят в состав MVP.

**Ограничения MVP**

Первая версия платформы разрабатывается при следующих ограничениях:

- один консультант;

- один клиент;

- один активный проект;

- один полностью завершённый консультационный цикл;

- ручное выполнение всех операций;

- простой административный интерфейс.

До завершения MVP не реализуются:

- Automation Engine;

- AI Agents;

- интеллектуальные рекомендации;

- автоматическое выполнение процессов;

- сложный пользовательский интерфейс;

- многопользовательский режим;

- распределённая работа;

- оптимизация производительности;

- организационная память.

**Критерий завершения MVP**

MVP считается завершённым после успешного выполнения полного
консультационного цикла, в результате которого:

- зарегистрировано первичное обращение;

- выполнен Check-up;

- подготовлено Proposal;

- оформлено Offer;

- выполнена работа в Workspace;

- сформирован итоговый Certificate;

- комплект результативной документации передан клиенту.

Все этапы выполняются средствами платформы без обращения к внешним
инструментам.

**Репозиторий проекта**

В процессе выполнения MVP все создаваемые артефакты сохраняются в
Repository.

Repository является единым хранилищем проектных материалов и
используется для накопления опыта разработки и оказания услуг.

Repository не выполняет анализ, интерпретацию или автоматическое
извлечение знаний.

**Правило трёх (Rule of Three)**

После успешного завершения трёх реальных консультационных проектов
проводится анализ выполненных операций.

Автоматизации подлежат только действия, которые:

- повторялись во всех проектах;

- имеют стабильный алгоритм выполнения;

- доказали практическую ценность.

Анализ проводится консультантом. Результаты анализа фиксируются в виде предложений по автоматизации и утверждаются владельцем платформы.

До выполнения данного условия все операции выполняются консультантом
вручную.

**Развитие платформы**

После подтверждения работоспособности MVP развитие SSP осуществляется
последовательно.

**Этап 2**

Автоматизация повторяющихся операций.

**Этап 3**

Подключение интеллектуальных помощников (AI).

**Этап 4**

Формирование организационной памяти.

**Этап 5**

Развитие пользовательского интерфейса.

**Этап 6**

Поддержка нескольких консультантов, клиентов и проектов.

Переход к следующему этапу допускается только после успешного завершения
предыдущего.

**Принцип развития**

SSP развивается не путём предварительного создания универсальной
платформы, а путём последовательного подтверждения работоспособности
каждого уровня системы.

Каждый следующий этап развития основывается исключительно на опыте
эксплуатации предыдущего.


**Границы MVP**

Соглашение о публикации документов

В рамках MVP все результативные документы (Check-up Report, Estimation Report, Offer Contract, Acceptance Certificate) проходят через два состояния:

Draft — создан, редактируется, не используется другими модулями;

Published — утверждён консультантом, доступен для использования следующими модулями.

Переход из Draft в Published выполняется исключительно явным действием консультанта через интерфейс платформы.

Соглашение о статусах проекта

Проект в MVP проходит следующие статусы:

*DRAFT* — зарегистрирован, но коммерческое предложение не оплачено;

*IN_PROGRESS* — оплата получена, выполняются работы;

*ON_HOLD* — выполнение приостановлено (по инициативе консультанта или клиента);

*WAITING_CLIENT* — ожидание ответа или материалов от клиента;

*REVIEW* — результаты переданы клиенту на проверку;

*COMPLETED* — все работы выполнены, готовится акт;

*CLOSED* — акт подписан, проект завершён.
