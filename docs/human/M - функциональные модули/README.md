# Раздел M — MVP и дорожная карта разработки

## Назначение раздела

Раздел **M** описывает минимально жизнеспособный продукт (MVP) цифровой платформы **Simple Solutions Practice (SSP)**, его границы, ограничения, архитектуру и последовательность разработки модулей.

Документы этого раздела определяют:
- цель и границы MVP;
- критерии завершения;
- архитектурные ограничения первой версии;
- последовательность разработки модулей;
- принципы накопления опыта (Organizational Memory).

Раздел M является мостом между бизнес-архитектурой (раздел B), технической архитектурой (раздел C) и инжиниринговыми решениями (раздел E).

---

## Перечень документов раздела

### 1. M-001 Дорожная карта разработки MVP

**Назначение:**  
Определяет состав, границы, ограничения и последовательность разработки первой рабочей версии SSP. Описывает цель MVP, критерии завершения, принцип "Правило трёх" и этапы развития платформы.

**Содержание:**
- Цель MVP
- Границы MVP (бизнес-процесс: Lead → Check-up → Estimation → Offer → Workspace → Execution → Certificate)
- Ограничения MVP (один консультант, один клиент, один проект, ручное выполнение)
- Критерий завершения MVP
- Репозиторий проекта
- Правило трёх (Rule of Three)
- Этапы развития платформы (6 этапов)
- Принцип развития (последовательное подтверждение работоспособности)
- Соглашение о публикации документов (Draft → Published)
- Соглашение о статусах проекта (DRAFT → IN_PROGRESS → ON_HOLD → WAITING_CLIENT → REVIEW → COMPLETED → CLOSED)

### 2. M-101 Ядро системы (Platform Kernel)

**Статус:** MVP | **Приоритет:** P0

**Назначение:**  
Реализовать минимальное ядро платформы, обеспечивающее регистрацию модулей, выполнение Workflow и сохранение результатов. Kernel не содержит бизнес-логики, только оркестрацию.

**Реализуемые компоненты:**
- Module Registry — регистрация модулей при запуске
- Capability Registry — регистрация и вызов Capability
- Workflow Engine — выполнение Workflow (LINEAR, CONDITIONAL, RETRY)
- Event Engine — регистрация Business Event и System Event
- Artifact Storage — сохранение и получение Artifact

**Технический стек:** Python 3.13, FastAPI, Pydantic v2, SQLAlchemy, PostgreSQL, Alembic, Docker Compose, Nginx, React, TypeScript, Vite

---

### 3. M-102 Модуль первичных обращений (Lead Intake)

**Статус:** MVP | **Приоритет:** P0

**Назначение:**  
Реализовать модуль приёма первичных обращений клиентов. Обеспечить регистрацию нового клиента, создание карточки проекта и запуск первичного бизнес-процесса.

**Реализуемые функции:**
- Приём заявки через веб-интерфейс
- Карточка клиента (создание нового или связывание с существующим)
- Карточка проекта (автоматическое создание)
- Business Event: **LeadRegistered**
- Запуск Workflow первичной обработки
- Сохранение заявки как Artifact

**Минимальный состав данных:** название компании, контактное лицо, телефон, e-mail, описание запроса, источник обращения, дата регистрации.

### 4. M-103 Рабочая область (Project Workspace)

**Статус:** MVP | **Приоритет:** P0

**Назначение:**  
Реализовать единое рабочее пространство проекта для хранения всей информации, документов, результатов анализа и истории работы.

**Реализуемые функции:**
- Автоматическое создание Workspace после регистрации проекта
- Структура проекта (карточка проекта, клиента, статус, список Artifact, история событий)
- Хранение документов и результатов
- История проекта (хронологический порядок)
- Навигация по активным проектам

---

### 5. M-104 Сбор первичных данных (Check-up)

**Статус:** MVP | **Приоритет:** P0

**Назначение:**  
Реализовать модуль проведения операционного Check-up организации: диагностика бизнеса, анализ информации, определение объёма проекта и расчёт стоимости.

**Реализуемые Capability:**
- **Diagnostic Interview** — структурированная диагностика по тематическим блокам (8 разделов). Результат: **Check-up Report**.
- **Project Estimation** — подготовка экспертной оценки: перечень работ, объём, трудоёмкость, стоимость, сроки. Результат: **Estimation Report**.

**Business Events:** CheckupCompleted, ProjectEstimated.

**Правило публикации:** результаты считаются черновиками до явного подтверждения консультантом (действие "Опубликовать оценку").

---

### 6. M-105 Подготовка договора-оферты (Offer Contract)

**Статус:** MVP | **Приоритет:** P0

**Назначение:**  
Реализовать модуль подготовки договора-оферты на основании утверждённой оценки проекта, ожидание оплаты и автоматический запуск проекта.

**Реализуемые функции:**
- Формирование договора-оферты на основании Estimation Report
- Регистрация Artifact: **Offer Contract**
- Статусы документа: Draft, Sent, Published, Awaiting Payment, Accepted, Expired, Cancelled
- Business Events: **OfferPublished**, **OfferAccepted**
- Автоматический перевод проекта в статус IN_PROGRESS после оплаты
- Поддержка повторной подготовки (новая редакция)

---

### 7. M-106 Сопровождение выполнения проекта (Project Execution)

**Статус:** MVP | **Приоритет:** P0

**Назначение:**  
Реализовать модуль сопровождения выполнения консалтингового проекта: контроль жизненного цикла, фиксация результатов, накопление материалов.

**Реализуемые функции:**
- Управление состоянием проекта (IN_PROGRESS, ON_HOLD, WAITING_CLIENT, REVIEW, COMPLETED)
- Рабочий журнал (фиксация действий, встреч, консультаций, документов, результатов)
- Хранение материалов проекта
- Хранение промежуточных результатов как Artifact
- История проекта (полностью воспроизводимая)
- Business Event: **ProjectCompleted**

**Таблица переходов статусов проекта:**
| Текущий статус | Событие | Новый статус |
|----------------|---------|--------------|
| IN_PROGRESS | ProjectSuspended | ON_HOLD |
| ON_HOLD | ProjectResumed | IN_PROGRESS |
| IN_PROGRESS | ClientActionRequired | WAITING_CLIENT |
| WAITING_CLIENT | ClientResponseReceived | IN_PROGRESS |
| IN_PROGRESS | ResultsSubmitted | REVIEW |
| REVIEW | ResultsAccepted | COMPLETED |
| COMPLETED | ProjectClosed | CLOSED |

**Статус:** MVP | **Приоритет:** P0

**Назначение:**  
Реализовать модуль завершения проекта: подготовка акта выполненных работ, закрытие проекта и передача в Organizational Memory.

**Реализуемые функции:**

- Закрытие проекта (статус → CLOSED)
- Business Event: **ProjectClosed**

### 9. M-108 Принципы накопления опыта (Organizational Memory)

**Статус:** MVP (принципы) | **Приоритет:** P1

**Назначение:**  
Определить принципы накопления, хранения и оптимизации практического опыта платформы.

**Принципы:**
- OM-001: Все Artifact автоматически сохраняются, удаление не допускается
- OM-002: Накопительное хранилище практического опыта
- OM-003: Оптимизация выполняется периодически отдельным процессом
- OM-004: Оптимизация включает поиск дублей, объединение, снижение рейтинга, выявление устаревших, архивирование, повышение рейтинга успешных
- OM-005: Каждый Artifact имеет показатели качества (количество использований, успешность, дата использования, рейтинг, статус актуальности)
- OM-006: Постепенное повышение качества без потери подтверждённого опыта

**Архитектурное правило:** Платформа не удаляет опыт. Платформа постоянно повышает качество накопленного опыта.
