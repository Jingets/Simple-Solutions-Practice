**S-003 Стандарты базы данных**

**Статус:** MVP

**Приоритет:** P0

**Цель**

Настоящий документ определяет единый стандарт проектирования, хранения и сопровождения данных платформы Simple Solutions Practice.

Все базы данных платформы должны соответствовать настоящему стандарту.

**Основной принцип**

База данных является единственным источником истины (Single Source of Truth).

Бизнес-данные должны существовать только в одном экземпляре.

Дублирование данных запрещается.

**Система управления базами данных**

Для MVP используется:

- PostgreSQL

Использование других СУБД допускается только после утверждения новой версии архитектуры.

**Доступ к данным**

Все обращения к базе данных выполняются исключительно через Repository Layer.

Прямой доступ к базе данных из:

- API;

- Business Module;

- Frontend;

запрещён.

**ORM**

Используется исключительно SQLAlchemy 2.x.

Использование нескольких ORM одновременно запрещено.

**Первичные ключи**

Все бизнес-объекты используют UUID.

Автоинкрементные идентификаторы допускаются только для внутренних технических таблиц.

**Именование**

**Таблицы**

snake\_case

множественное число

Пример

projects

business\_events

artifacts

**Поля**

snake\_case

Пример

created\_at

project\_id

status

**Обязательные служебные поля**

Каждая бизнес-таблица должна содержать:

- id

- created\_at

- updated\_at

- created\_by

- updated\_by

При необходимости:

- deleted\_at

**Удаление данных**

Физическое удаление бизнес-данных запрещено.

Используется Soft Delete.

Удаление выполняется изменением состояния объекта.

**Нормализация**

Используется нормализация не ниже третьей нормальной формы (3NF).

Денормализация допускается только после документированного обоснования.

**Связи**

Все внешние ключи должны быть явно определены.

Использование неявных связей запрещено.

**Миграции**

Все изменения структуры базы данных выполняются исключительно через Alembic.

Ручное изменение структуры базы данных запрещено.

**Индексы**

Индексы создаются:

- для первичных ключей;

- внешних ключей;

- полей поиска;

- полей фильтрации.

Избыточное индексирование запрещено.

**Транзакции**

Все операции изменения бизнес-данных должны выполняться в транзакции.

Частично завершённые изменения не допускаются.

**Целостность данных**

Каждая запись должна находиться в согласованном состоянии.

Нарушение ссылочной целостности запрещено.

**Версионирование данных**

Документы платформы (Artifact) должны поддерживать хранение версий.

Изменение существующей версии запрещено.

Каждая новая редакция создаёт новую версию.

**Audit**

Все критические изменения должны фиксироваться в Audit Log.

Минимально регистрируются:

- создание;

- изменение;

- изменение статуса;

- удаление (Soft Delete).

**Производительность**

Запрещается:

- SELECT \*;

- N+1 запросы;

- необоснованные JOIN большого объёма;

- выполнение тяжёлых запросов в пользовательских Workflow.

**Backup**

База данных должна поддерживать регулярное резервное копирование.

Политика резервного копирования определяется отдельно.

**Архитектурные ограничения**

База данных не содержит бизнес-логики.

Все вычисления выполняются в сервисном слое.

Использование триггеров для реализации бизнес-процессов запрещено.

**Definition of Done**

Структура базы данных считается соответствующей стандарту, если:

- используется PostgreSQL;

- применяется SQLAlchemy;

- все изменения выполняются через Alembic;

- отсутствует физическое удаление бизнес-данных;

- реализована ссылочная целостность;

- соблюдаются правила именования;

- реализованы обязательные служебные поля;

- поддерживается аудит изменений.

**Главный принцип**

Структура данных должна обеспечивать долговременное накопление организационного опыта, возможность воспроизведения любого бизнес-события и безопасное развитие платформы без потери исторических данных.
