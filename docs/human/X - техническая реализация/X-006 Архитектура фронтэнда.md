**X-006 Архитектура фронтэнда**

**Статус:** MVP

**Приоритет:** P0

**Цель**

Настоящий документ определяет архитектуру клиентской части платформы Simple Solutions Practice.

Документ является технической спецификацией для реализации Frontend MVP.

Frontend должен обеспечивать работу пользователя с платформой и не содержать бизнес-логики.

**Основной принцип**

Frontend отвечает исключительно за:

- отображение информации;

- получение пользовательского ввода;

- вызов Backend API;

- отображение результатов.

Все бизнес-решения принимаются Backend.

**Используемые технологии**

Frontend MVP реализуется с использованием:

- React 18+

- TypeScript

- Vite

- React Router

- TanStack Query

- Tailwind CSS

**Структура страниц MVP**

Для первой версии платформы реализуются следующие страницы:

- Login

- Dashboard

- Leads

- Project

- Check-up

- Estimation

- Offer Contract

- Workspace

- Artifacts

- Acceptance Certificate

Добавление новых страниц допускается только после расширения MVP.

**Dashboard**

Отображает:

- количество новых Lead;

- активные проекты;

- проекты, ожидающие оценки;

- проекты, ожидающие оплаты;

- завершённые проекты.

Dashboard не содержит функций редактирования.

**Lead Page**

Позволяет:

- зарегистрировать обращение;

- просмотреть список обращений;

- открыть карточку обращения.

**Project Page**

Отображает:

- карточку проекта;

- текущий статус;

- связанные сущности;

- историю проекта.

**Check-up Page**

Позволяет:

- просматривать результаты диагностики;

- запускать создание нового Check-up;

- открывать предыдущие версии.

**Estimation Page**

Позволяет:

- просматривать расчёт стоимости;

- инициировать создание договора-оферты.

Расчёт выполняется Backend.

**Offer Contract Page**

Отображает:

- договор-оферту;

- сумму;

- статус оплаты.

Редактирование стоимости запрещено.

**Workspace Page**

Предоставляет доступ ко всем материалам проекта.

Отображает:

- документы;

- артефакты;

- историю изменений.

**Artifacts Page**

Позволяет:

- просматривать артефакты;

- скачивать артефакты;

- просматривать версии.

Изменение Artifact запрещено.

**Acceptance Certificate Page**

Позволяет:

- просмотреть акт;

- сформировать PDF;

- завершить проект.

**Навигация**

Главное меню MVP:

Dashboard

Leads

Projects

Artifacts

Рабочие страницы открываются из карточки проекта.

**API**

Frontend взаимодействует исключительно через Backend API.

Прямой доступ к базе данных запрещён.

**Управление состоянием**

Локальное состояние используется только для интерфейса.

Источник бизнес-данных — Backend.

**Обработка ошибок**

Все ошибки Backend отображаются пользователю в понятной форме.

Frontend не интерпретирует ошибки самостоятельно.

**Архитектурные ограничения**

Запрещается:

- бизнес-логика во Frontend;

- вычисление стоимости проекта;

- изменение Workflow;

- работа с базой данных;

- создание Business Event.

**Definition of Done**

Frontend считается реализованным, если:

- доступны все страницы MVP;

- реализована навигация;

- все действия выполняются через Backend API;

- отсутствует бизнес-логика;

- интерфейс позволяет пройти полный цикл MVP от регистрации Lead до завершения проекта.

**Главный принцип**

Frontend платформы SSP является тонким клиентом, который отображает состояние системы и передаёт действия пользователя Backend, не принимая самостоятельных бизнес-решений.
