**X-002 Физическая модель данных**

**Статус:** MVP

**Приоритет:** P0

**Цель**

Настоящий документ определяет физическую модель хранения данных платформы Simple Solutions Practice.

Документ является основой для проектирования схемы PostgreSQL, моделей SQLAlchemy и миграций Alembic.

**Основной принцип**

Физическая модель является реализацией доменной модели, определённой в документе X-001.

Структура базы данных не должна изменять бизнес-смысл доменных сущностей.

**Общая структура базы данных**

Для MVP используются следующие основные таблицы:

customers

leads

projects

checkups

estimation\_reports

offer\_contracts

project\_workspaces

artifacts

business\_events

system\_events

acceptance\_certificates

organizational\_memory\_entries

**Общие требования**

Каждая бизнес-таблица обязана содержать следующие поля:

- id (UUID)

- created\_at

- updated\_at

- created\_by

- updated\_by

При необходимости:

- deleted\_at (Soft Delete)

**Правила связей**

Допускаются только явные связи через Foreign Key.

Использование неявных ссылок запрещено.

**Правила удаления**

Физическое удаление бизнес-данных запрещено.

Используется Soft Delete в соответствии со стандартом S-003.

**Индексирование**

Обязательные индексы:

- все Primary Key;

- все Foreign Key;

- project\_id;

- created\_at;

- status.

Дополнительные индексы создаются только при подтверждённой необходимости.

**Версионирование**

Версионируемые сущности:

- Check-up;

- Estimation Report;

- Offer Contract;

- Artifact;

- Acceptance Certificate.

Новая редакция создаёт новую запись или новую версию в соответствии с политикой версионирования.

**Архитектурные ограничения**

Структура базы данных не содержит бизнес-логики.

Все вычисления выполняются в сервисном слое.

Все изменения структуры выполняются исключительно через миграции Alembic.

**Definition of Done**

Физическая модель считается утверждённой, если:

- все сущности X-001 представлены таблицами;

- определены все основные связи;

- определены обязательные поля;

- отсутствуют неоднозначные зависимости;

- модель может быть автоматически преобразована в SQLAlchemy Models и Alembic Migration без изменения структуры.

**Главный принцип**

Физическая модель данных должна быть прямым и однозначным отображением доменной модели платформы, обеспечивая простоту реализации, расширяемость и сохранность бизнес-данных.
