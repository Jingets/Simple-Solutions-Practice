# X-001. Доменная модель

## 1. Назначение

Документ определяет каноническую доменную модель Pilot MVP платформы Simple Solutions Practice.

Все бизнес-сущности, события, состояния и связи строятся на основании настоящей модели.

Физическая модель БД, API и генерация документов не должны противоречить настоящему документу.

---

# 2. Основные принципы

Доменная модель строится по следующим правилам:

- каждая бизнес-сущность имеет собственный жизненный цикл;
- изменение состояния выполняется только через Business Event;
- все связи между сущностями определены явно;
- Platform Kernel не содержит бизнес-сущностей;
- Artifact является результатом выполнения процесса, а не самим процессом;
- Business Event является единственным источником достоверной информации об изменении состояния.

# 4. Lead

Потенциальный клиент.

Основные атрибуты:

- id
- created_at
- full_name
- company_name
- email
- phone
- source
- status

Связи:

- Lead → Customer (0..1)

---

# 5. Customer

Заказчик консультационных услуг.

Основные атрибуты:

- id
- legal_name
- short_name
- inn
- ogrn
- contact_person
- email
- phone

Связи:

- Customer → Projects (1..N)

---

# 6. Project

Основная бизнес-сущность платформы.

Project объединяет все артефакты консультационной работы.

Основные атрибуты:

- id
- number
- customer_id
- service_id
- manager_id
- current_status
- created_at
- updated_at

---

# 7. Канонические статусы Project

```text
DRAFT
IN_PROGRESS
ON_HOLD
WAITING_CLIENT
REVIEW
COMPLETED
CLOSED
```

Другие статусы в Pilot MVP запрещены.

---

# 8. Workspace

Рабочее пространство проекта.

Содержит:

- документы;
- файлы;
- комментарии;
- историю.

Workspace принадлежит одному Project.

---

# 9. Checkup

Результат диагностики организации.

Основные атрибуты:

- id
- project_id
- completed_at
- author_id

Результатом является Check-up Report.

---

# 10. Estimation

Оценка проекта.

Содержит:

- стоимость;
- срок;
- объём работ;
- описание решения.

Результатом является Estimation Report.

---

# 11. Offer

Коммерческая оферта.

Содержит:

- реквизиты;
- стоимость;
- условия;
- ссылку на Estimation.

Результатом является Offer Contract.

---

# 12. Invoice

Счёт на оплату.

Основные поля:

- номер;
- сумма;
- дата;
- статус оплаты.

Invoice связан с одной Offer.

---

# 13. Acceptance Certificate

Документ завершения проекта.

Создаётся после успешного завершения работ.

---

# 14. Artifact

Любой сформированный документ платформы.

Минимальные атрибуты:

- id
- artifact_type
- project_id
- version
- storage_uri
- checksum
- created_at

Типы Artifact:

- CHECKUP_REPORT
- ESTIMATION_REPORT
- OFFER_CONTRACT
- INVOICE
- ACCEPTANCE_CERTIFICATE

---

# 15. Business Event

Неизменяемая запись изменения бизнес-состояния.

Минимальные атрибуты:

```yaml
event_id: uuid
event_type: string
aggregate_type: string
aggregate_id: uuid
occurred_at: datetime
actor_id: uuid | null
correlation_id: uuid
payload: object
```

Business Event никогда не редактируется.

---

# 16. Service

Каталог оказываемых услуг.

Минимальные поля:

- id
- code
- name
- description
- active

Project всегда связан с одной Service.

---

# 17. Platform Legal Profile

Юридическое лицо, от имени которого оформляются документы.

Основные поля:

- id
- legal_name
- inn
- ogrn
- kpp
- address
- bank_account
- correspondent_account
- bik
- bank_name
- signer_name
- signer_position

Используется генерацией всех юридических документов.

---

# 18. User

Пользователь платформы.

Минимальные роли:

```text
ADMIN
MANAGER
SYSTEM
```

Customer не является User в Pilot MVP.

# 22. Ограничения

Запрещено:

- добавлять новые статусы Project;
- изменять имена событий;
- связывать Customer с User;
- изменять состояние без Business Event;
- хранить документы вне Artifact.
