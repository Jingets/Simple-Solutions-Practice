**X-007 Архитектура развёртывания**

**Статус:** MVP

**Приоритет:** P0

**Цель**

Настоящий документ определяет архитектуру развёртывания платформы Simple Solutions Practice MVP.

Документ является технической спецификацией для сборки рабочей среды разработки и эксплуатации MVP.

**Основной принцип**

Платформа должна запускаться полностью с помощью одного Docker Compose проекта.

Развёртывание не должно требовать ручной настройки компонентов после первоначальной конфигурации.

**Используемые технологии**

Для MVP используются:

- Docker

- Docker Compose

- Nginx

- FastAPI

- PostgreSQL

- React

- Certbot (для production)

Использование Kubernetes, Service Mesh и других систем оркестрации в MVP не допускается.

**Контейнеры MVP**

Обязательный состав:

nginx

frontend

backend

postgres

nats — NATS JetStream для Event Bus

Дополнительные сервисы могут быть добавлены после завершения MVP.

**Docker Network**

Создаётся единая внутренняя сеть:

ssp-network

Все контейнеры подключаются только к данной сети.

**Volumes**

Используются постоянные тома:

postgres\_data

artifacts\_storage

nginx\_logs

Данные PostgreSQL и Artifact должны сохраняться между перезапусками.

**Artifact Storage**

Для MVP используется локальное файловое хранилище.

/artifacts

Backend обращается к нему исключительно через Artifact Manager.

Прямой доступ Frontend запрещён.

**Переменные окружения**

Минимальный набор:

POSTGRES\_HOST

POSTGRES\_PORT

POSTGRES\_DB

POSTGRES\_USER

POSTGRES\_PASSWORD

SECRET\_KEY

ARTIFACT\_STORAGE\_PATH

API\_BASE\_URL

FRONTEND\_BASE\_URL

Все параметры задаются через .env.

Использование "зашитых" значений в коде запрещено.

**Backend**

Backend публикует только REST API.

Все входящие запросы проходят через Nginx.

**Frontend**

Frontend представляет собой статическую сборку.

Раздаётся через Nginx.

**PostgreSQL**

Используется одна база данных.

Создание структуры выполняется миграциями Alembic.

Ручное изменение схемы запрещено.

**Nginx**

Выполняет:

- TLS Termination;

- Reverse Proxy;

- раздачу Frontend;

- маршрутизацию запросов к Backend.

**HTTPS**

Production использует HTTPS.

Сертификаты выпускаются через Certbot.

В локальной среде допускается HTTP.

**Логирование**

Логи разделяются по компонентам:

- nginx;

- backend;

- frontend;

- postgres.

Логи сохраняются независимо от данных приложения.

**Backup**

Для MVP предусматривается резервное копирование:

- PostgreSQL;

- Artifact Storage.

Организационная память должна входить в резервную копию автоматически.

**Масштабирование**

MVP ориентирован на один экземпляр Backend.

Поддержка горизонтального масштабирования не является целью первой версии.

Архитектура должна допускать масштабирование без изменения бизнес-модулей.

**Архитектурные ограничения**

Запрещается:

- прямой доступ Frontend к PostgreSQL;

- публикация PostgreSQL во внешнюю сеть;

- хранение секретов в исходном коде;

- хранение Artifact внутри контейнера Backend.

**Запуск платформы**

После выполнения команды:

docker compose up -d

должны быть автоматически доступны:

- Frontend;

- Backend API;

- PostgreSQL;

- Platform Kernel.

Дополнительные ручные действия не требуются.

**Definition of Done**

Архитектура развёртывания считается реализованной, если:

- платформа запускается одной командой;

- все сервисы автоматически обнаруживают друг друга;

- данные сохраняются между перезапусками;

- структура соответствует настоящей спецификации;

- отсутствуют ручные операции после первого запуска.

**Главный принцип**

Развёртывание MVP должно быть максимально простым, воспроизводимым и полностью автоматизированным.

Любой разработчик должен иметь возможность получить полностью работоспособную платформу, выполнив минимальное количество команд без изменения архитектуры проекта.
