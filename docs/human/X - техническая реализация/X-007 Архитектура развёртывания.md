# X-007. Архитектура развёртывания

## 1. Назначение

Документ определяет архитектуру развёртывания Pilot MVP платформы Simple Solutions Practice.

Все компоненты системы должны запускаться одной командой Docker Compose и обеспечивать воспроизводимое окружение для локальной разработки, тестирования и демонстрации MVP.

---

# 2. Цели развёртывания

Архитектура должна обеспечивать:

- быстрый запуск проекта;
- воспроизводимость окружения;
- одинаковое поведение локально и на сервере;
- простое обновление;
- минимальное количество инфраструктурных компонентов.

---

# 3. Архитектура Pilot MVP

Используется единый Docker Compose.

Все сервисы работают внутри одной сети Docker.

```text
                 Internet
                     │
                     ▼
                  nginx
                 /     \
                ▼       ▼
         Frontend    Backend
                         │
                         ▼
                   PostgreSQL
```

Все взаимодействия проходят через Backend.

Frontend не обращается к PostgreSQL напрямую.

---

# 4. Состав контейнеров

Обязательные контейнеры:

| Контейнер | Назначение |
|-----------|------------|
| nginx | Reverse Proxy |
| frontend | React SPA |
| backend | FastAPI |
| postgres | PostgreSQL |

Дополнительно допускаются одноразовые контейнеры:

- alembic migration;
- integration tests;
- E2E tests.

---

# 5. Docker Compose

Минимальный состав:

```text
docker-compose.yml
```

Должны быть определены сервисы:

```text
nginx
frontend
backend
postgres
```

Все сервисы подключаются к одной внутренней сети.

---

# 6. Backend

Backend предоставляет:

- REST API;
- OpenAPI;
- Business Logic;
- Platform Kernel;
- Artifact Generation;
- Authentication;
- Authorization.

Порт внутри контейнера:

```text
8000
```

---

# 7. Frontend

Frontend реализуется на React.

Порт разработки:

```text
5173
```

Во внешнюю сеть публикуется только через nginx.

---

# 8. Nginx

Nginx обеспечивает:

- раздачу frontend;
- проксирование API;
- поддержку HTTPS (при наличии сертификатов);
- отдачу статических файлов.

Во внешнюю сеть публикуются только:

```text
80
443
```

Backend не должен публиковаться напрямую.

---

# 9. PostgreSQL

Используется единая база данных.

Обязательные требования:

- Docker Volume;
- UTF-8;
- UUID;
- timezone UTC;
- автоматическое применение миграций перед запуском приложения.

Порт PostgreSQL наружу может не публиковаться.

---

# 10. Docker Volumes

Минимальный набор:

```text
postgres_data
artifacts_storage
```

Используются для:

- хранения БД;
- хранения сгенерированных документов.

---

# 11. Docker Network

Используется одна сеть.

Например:

```text
ssp-network
```

Все контейнеры взаимодействуют только через внутреннюю сеть.

---

# 12. Переменные окружения

Конфигурация хранится в `.env`.

Минимальный набор:

```text
POSTGRES_DB
POSTGRES_USER
POSTGRES_PASSWORD

DATABASE_URL

JWT_SECRET

JWT_EXPIRE_MINUTES

APP_URL

FRONTEND_URL

STORAGE_PATH
```

В репозитории хранится только `.env.example`.

---

# 13. Последовательность запуска

```text
docker compose up
        │
        ▼
PostgreSQL
        │
        ▼
Migration
        │
        ▼
Backend
        │
        ▼
Frontend
        │
        ▼
nginx
```

Backend не должен запускаться до успешного применения миграций.

---

# 14. Health Check

Backend обязан предоставлять:

```text
GET /health
```

Ответ:

```json
{
  "status": "ok"
}
```

Docker Healthcheck использует данный endpoint.

---

# 15. Проверка готовности

После запуска должны быть доступны:

```text
/
```

Frontend.

```text
/api/v1
```

REST API.

```text
/docs
```

OpenAPI.

```text
/health
```

Health Check.

---

# 16. Развёртывание на сервере

Минимальная последовательность:

```bash
git pull

docker compose build

docker compose up -d
```

После обновления должны автоматически применяться миграции.

---

# 17. Логирование

Каждый контейнер выводит лог в stdout/stderr.

Docker используется как единый механизм сбора логов.

Дополнительные системы логирования не входят в Pilot MVP.

---

# 18. Резервное копирование

Минимально резервируются:

- PostgreSQL;
- Artifacts.

Исходный код резервируется средствами Git.

---

# 19. Не входит в Pilot MVP

Не используются:

- Kubernetes;
- Helm;
- Docker Swarm;
- Redis;
- Kafka;
- NATS;
- Elasticsearch;
- Prometheus;
- Grafana;
- Service Mesh;
- API Gateway.

---

# 20. Критерии готовности

Развёртывание считается успешным если:

- выполняется

```bash
docker compose up -d
```

- backend подключается к PostgreSQL;
- миграции проходят;
- frontend открывается;
- OpenAPI доступен;
- Health Check возвращает OK;
- возможно прохождение полного сценария Pilot MVP.
