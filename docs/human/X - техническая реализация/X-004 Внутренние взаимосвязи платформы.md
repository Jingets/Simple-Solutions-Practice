# X-004. Внутренние взаимосвязи платформы

## 1. Назначение

Документ определяет внутренние взаимосвязи между модулями, доменными сущностями, Business Events и Platform Kernel в рамках Pilot MVP.

Настоящий документ является каноническим описанием жизненного цикла проекта и последовательности взаимодействия компонентов платформы.

# 6. Business Events

Минимальный набор событий:

```text
LeadRegistered
ProjectCreated
WorkspaceCreated
CheckupCompleted
ProjectEstimated
OfferPublished
InvoiceGenerated
PaymentRegistered
OfferAccepted
ProjectSuspended
ProjectResumed
ClientActionRequired
ClientResponseReceived
ResultsSubmitted
ResultsAccepted
ProjectCompleted
AcceptanceCertificateGenerated
ProjectClosed
```

Каждое событие:

- неизменяемо;
- имеет UUID;
- имеет Correlation ID;
- сохраняется в одной транзакции с изменением состояния.

---

# 7. Platform Kernel

Platform Kernel обеспечивает:

- Module Registry;
- Capability Registry;
- Event Dispatcher;
- Workflow Dispatcher;
- Artifact Manager;
- Business Event Store.

Kernel не содержит бизнес-логики модулей.

---

# 8. Взаимодействие модулей

Модули взаимодействуют только через:

- Capability;
- Business Event;
- публичные контракты.

Запрещено:

- обращаться к внутренним Repository другого модуля;
- использовать внутренние ORM-модели другого модуля;
- изменять состояние другого модуля напрямую.

# 10. Генерация документов

Artifact Manager получает запрос на генерацию после успешного завершения соответствующей Capability.

Источник данных:

- Project;
- Customer;
- Platform Legal Profile;
- Service;
- соответствующая бизнес-сущность;
- YAML;
- Markdown Template.

Результат:

- Markdown;
- PDF (при необходимости);
- запись Artifact.

# 13. Взаимодействие API и событий

Любое изменение состояния выполняется по следующей схеме:

```text
HTTP Request
      │
      ▼
Validation
      │
      ▼
Capability
      │
      ▼
Business Rules
      │
      ▼
Repository
      │
      ▼
Commit
      │
      ├────────► Business Event
      │
      ▼
HTTP Response
```

Изменение состояния без публикации Business Event запрещено.

---

# 14. Ограничения

Запрещено:

- менять состояние напрямую через Repository;
- создавать Business Event вне транзакции;
- использовать события, отсутствующие в X-001;
- изменять состояние без проверки допустимого перехода;
- использовать внутренние классы другого модуля.

---

# 15. Проверка целостности

При запуске системы должны быть проверены:

- регистрация всех модулей;
- регистрация Capability;
- регистрация маршрутов API;
- регистрация Business Events;
- регистрация шаблонов документов;
- регистрация YAML-описаний;
- доступность Platform Legal Profile.

При отсутствии обязательного компонента запуск Platform Kernel должен завершаться ошибкой.
