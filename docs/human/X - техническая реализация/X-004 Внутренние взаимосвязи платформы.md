**X-004 Внутренние взаимосвязи платформы**

**Статус:** MVP

**Приоритет:** P0

**Цель**

Настоящий документ определяет взаимосвязи между доменными сущностями платформы Simple Solutions Practice и допустимые переходы их состояний.

Документ является основой для реализации:

- SQLAlchemy Relationships;

- Workflow Engine;

- Business Rules;

- Repository Layer;

- API Validation.

**Основной принцип**

Каждая сущность имеет:

- определённые связи с другими сущностями;

- собственный жизненный цикл;

- допустимые переходы состояний.

Изменение состояния допускается только через Workflow Engine.

│

WAITING_CLIENT

Обратные переходы запрещены.

Переход через несколько состояний запрещён.

Каждый переход статуса Project регистрирует Business Event: ProjectCreated, CheckupStarted, CheckupCompleted, EstimationCreated, EstimationPublished, ContractCreated, ContractSent, ContractAccepted, ProjectStarted, ProjectSuspended, ProjectResumed, ClientActionRequired, ClientResponseReceived, ResultsSubmitted, ResultsAccepted, ProjectCompleted, ProjectClosed.

**Organizational Memory**

Создаётся только после перехода Project в состояние:

COMPLETED

Для создания записи должны существовать:

- Acceptance Certificate;

- финальные Artifact;

- полный набор Business Event.

**Business Event**

Business Event создаётся автоматически при каждом изменении бизнес-состояния.

Business Event:

- не изменяется;

- не удаляется;

- не архивируется.

**System Event**

System Event создаётся Platform Kernel.

Не влияет на бизнес-процесс.

Используется для технического аудита.

**Ограничения связей**

Project не может существовать без Lead.

Check-up не может существовать без Project.

Estimation Report не может существовать без Check-up.

Offer Contract не может существовать без Estimation Report.

Acceptance Certificate не может существовать без завершённого Project.

Organizational Memory Entry не может существовать без Acceptance Certificate.

**Каскадные правила**

Удаление бизнес-сущностей запрещено.

При архивировании Project:

- связанные записи не удаляются;

- связи сохраняются;

- история остаётся доступной.

**Workflow Validation**

Workflow Engine обязан проверять:

- допустимость перехода;

- наличие обязательных сущностей;

- выполнение Platform Policy;

- регистрацию Business Event.

Недопустимый переход должен быть отклонён.

**Автоматическая генерация**

На основании настоящей спецификации автоматически формируются:

- SQLAlchemy Relationships;

- Foreign Keys;

- Workflow Validation Rules;

- State Machine;

- API Validation Rules.

**Definition of Done**

Модель считается завершённой, если:

- определены все связи между сущностями;

- определены допустимые кардинальности;

- определены жизненные циклы всех сущностей MVP;

- определены допустимые переходы состояний;

- отсутствуют неоднозначные маршруты переходов.

**Главный принцип**

Связи между сущностями и переходы состояний определяются исключительно настоящей спецификацией.

Ни один компонент платформы не имеет права изменять состояние бизнес-сущности в обход Workflow Engine.
