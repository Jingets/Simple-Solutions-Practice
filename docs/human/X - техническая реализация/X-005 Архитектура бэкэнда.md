**X-005 Архитектура бэкэнда**

**Статус:** MVP

**Приоритет:** P0

**Цель**

Настоящий документ определяет структуру серверной части платформы Simple Solutions Practice.

Документ является обязательной спецификацией для реализации Backend MVP.

Любая реализация Backend должна соответствовать настоящей структуре.

**Основной принцип**

Backend строится вокруг Platform Kernel.

Все бизнес-модули являются независимыми компонентами, взаимодействующими исключительно через Platform Kernel.

Прямое взаимодействие бизнес-модулей запрещено.

**Используемые технологии**

Backend MVP реализуется с использованием:

- Python 3.12+

- FastAPI

- SQLAlchemy 2.x

- Alembic

- PostgreSQL

- Pydantic v2

- Uvicorn

Замена технологий допускается только после изменения архитектурной документации.

**app/**

Точка запуска Backend.

Содержит:

- инициализацию приложения;

- регистрацию модулей;

- запуск Platform Kernel.

**kernel/**

Реализует ядро платформы.

Содержит:

- Module Registry;

- Capability Registry;

- Workflow Dispatcher;

- Event Dispatcher;

- Policy Engine;

- Artifact Manager.

Ядро не содержит бизнес-логики.

**modules/**

Содержит бизнес-модули платформы.

Каждый модуль располагается в отдельном каталоге.

Пример:

modules/

lead/

project/

checkup/

estimation/

contract/

workspace/

memory/

Каждый модуль реализует одну бизнес-функцию.

**repositories/**

Содержит слой доступа к данным.

Каждая сущность имеет собственный Repository.

Repository является единственной точкой доступа к базе данных.

**workflows/**

Содержит описание Workflow.

Workflow определяет последовательность переходов бизнес-состояний.

**artifacts/**

Содержит реализацию Artifact Manager.

Отвечает за:

- регистрацию;

- версии;

- хранение метаданных;

- получение Artifact.

**events/**

Содержит обработчики:

- Business Events;

- System Events.

**policies/**

Содержит Platform Policy.

Policy не изменяет данные.

Policy принимает решение:

- разрешить;

- запретить;

- вернуть причину отказа.

**models/**

SQLAlchemy Models.

Генерируются на основании документов серии X.

**schemas/**

Pydantic DTO.

Используются:

- API;

- Kernel;

- Modules.

**api/**

FastAPI Routers.

API не содержит бизнес-логики.

API выполняет:

- приём запроса;

- валидацию;

- вызов Capability;

- возврат результата.

**infrastructure/**

Технические сервисы платформы.

Например:

- Logging;

- Database;

- Storage;

- Cache;

- Mail;

- File Storage.

Не содержит бизнес-логики.

**config/**

Конфигурация платформы.

Все параметры читаются исключительно отсюда.

Использование конфигурации внутри кода напрямую запрещено.

**tests/**

Автоматические тесты.

Структура повторяет структуру Backend.

**main.py**

Единственная точка запуска приложения.

Обязан выполнять:

- загрузку конфигурации;

- регистрацию Platform Kernel;

- регистрацию модулей;

- запуск FastAPI.

Обратные зависимости запрещены.

**Архитектурные ограничения**

Запрещается:

- бизнес-логика в API;

- SQL в модулях;

- обращение модулей друг к другу;

- обращение Frontend к базе данных;

- изменение Workflow в обход Kernel;

- создание Artifact в обход Artifact Manager.

**Definition of Done**

Backend считается соответствующим архитектуре SSP, если:

- структура каталогов соответствует настоящему документу;

- все зависимости направлены сверху вниз;

- Platform Kernel является единственной точкой координации;

- бизнес-модули независимы;

- отсутствует дублирование ответственности между слоями.

**Главный принцип**

Backend платформы Simple Solutions Practice строится как модульная система, в которой Platform Kernel управляет взаимодействием независимых бизнес-модулей, обеспечивая масштабируемость, расширяемость и возможность постепенного развития MVP без изменения базовой архитектуры.
