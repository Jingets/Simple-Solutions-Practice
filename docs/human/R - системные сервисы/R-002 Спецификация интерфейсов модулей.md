**R-002 Спецификация интерфейсов модулей**

**Статус:** MVP

**Приоритет:** P0

**Цель**

Настоящий документ определяет единый контракт взаимодействия между Platform Kernel и бизнес-модулями платформы Simple Solutions Practice.

Каждый модуль платформы обязан реализовывать настоящий интерфейс.

Любой модуль, не соответствующий настоящему контракту, не может быть зарегистрирован Platform Kernel.

**Общий принцип**

Platform Kernel ничего не знает о внутреннем устройстве модуля.

Kernel взаимодействует только через опубликованный интерфейс.

Модуль самостоятельно реализует свою внутреннюю архитектуру.

**Структура модуля**

Каждый модуль обязан содержать:

- Manifest;

- Capability Registry;

- Event Registry;

- Configuration;

- API Entry Point.

**Module Manifest**

Каждый модуль обязан предоставить Manifest.

Минимальный состав Manifest:

- Module ID;

- Module Name;

- Version;

- Description;

- Author;

- Status;

- Required Platform Version;

- Registered Capability;

- Published Events;

- Subscribed Events.

Manifest используется Platform Kernel при регистрации модуля.

**Capability Registry**

Каждый модуль обязан зарегистрировать все доступные Capability.

Для каждой Capability указываются:

- Identifier;

- Name;

- Description;

- Input Context - JSON-объект, содержащий данные, необходимые для выполнения Capability;

- Output Context - Output Context — JSON-объект, возвращаемый после выполнения.

Platform Kernel имеет право вызывать только зарегистрированные Capability.

**Event Registry**

Каждый модуль обязан определить:

**Published Events**

События, создаваемые модулем.

**Subscribed Events**

События, обрабатываемые модулем.

Все взаимодействие между модулями осуществляется исключительно через Business Event и System Event.

Прямой вызов одного бизнес-модуля другим запрещён.

**API Entry Point**

Каждый модуль обязан иметь единую точку входа.

Через неё Platform Kernel:

- вызывает Capability;

- передаёт Context;

- получает Result.

Внутреннее устройство модуля Platform Kernel не использует.

**Configuration**

Каждый модуль обязан поддерживать собственную конфигурацию.

Конфигурация не должна изменять поведение других модулей.

**Artifact Contract**

Если модуль создаёт документы или результаты работы, они обязаны регистрироваться как Artifact.

Artifact должен содержать:

- Artifact ID;

- Artifact Type;

- Project ID;

- Module ID;

- Version;

- Created At;

- Created By.

Artifact ID генерируется платформой автоматически при регистрации. Формат: ART-{UUID}.

**Context Contract**

Модуль получает Context исключительно от Platform Kernel.

Изменение Context допускается только в пределах собственной Capability.

Изменение глобального Context запрещено.

**Error Contract**

Каждый модуль обязан возвращать стандартизированный результат выполнения.

Минимальный состав результата:

- Status;

- Result;

- Errors;

- Warnings;

- Generated Artifact;

- Published Events.

---
json
{
"status": "success",
"result": {"estimation_id": "EST-001"},
"errors": [],
"warnings": [],
"generated_artifacts": ["ART-123"],
"published_events": ["CheckupCompleted"]
}
---

**Version Contract**

Каждый модуль обязан поддерживать собственную версию.

Platform Kernel проверяет совместимость версии модуля перед регистрацией.

Несовместимые версии не загружаются.

**Dependency Contract**

Модуль может зависеть только от:

- Platform Kernel;

- Shared Library.

Shared Library содержит: общие утилиты (логгирование, валидация, работа с датами), базовые классы для Artifact, Event, Context. Размещается в backend/shared/.

Прямые зависимости между бизнес-модулями запрещены. 

Обмен информацией выполняется исключительно через:

- Capability;

- Business Event;

- System Event;

- Artifact.

**Module Lifecycle**

Каждый модуль обязан поддерживать жизненный цикл:

- Registration

- Initialization

- Active

- Suspended

- Disabled

- Removed

Переходы между состояниями выполняются только Platform Kernel.

Таблица переходов:

Текущее состояние	Событие	Новое состояние

-------------------	---------	-----------------	
Registration	ModuleRegistered	Initialization	
Initialization	ModuleInitialized	Active	
Active	ModuleSuspended	Suspended	
Suspended	ModuleResumed	Active	
Active	ModuleDisabled	Disabled	
Disabled	ModuleRemoved	Removed
-------------------	---------	-----------------

**Архитектурные ограничения**

Модуль не имеет права:

- изменять Platform Kernel;

- изменять другие модули;

- обращаться к внутренним компонентам другого модуля;

- использовать внутренние структуры Platform Kernel;

- изменять Organizational Memory напрямую.

**Definition of Done**

Модуль считается соответствующим архитектуре SSP, если:

- успешно проходит регистрацию;

- публикует Manifest;

- регистрирует Capability;

- регистрирует Events;

- корректно принимает Context;

- корректно возвращает Result;

- создаёт Artifact согласно контракту;

- не нарушает модульную изоляцию.

**Пример модуля**

*Checkup:*
Manifest: {id: "checkup", version: "1.0", capabilities: ["diagnostic_interview", "project_estimation"]}
Capability: diagnostic_interview → Input: {project_id}, Output: {checkup_report_id}

**Результат**

После утверждения настоящего документа все существующие и будущие модули платформы получают единый контракт взаимодействия с Platform Kernel.

Это обеспечивает независимую разработку, заменяемость внутренних реализаций и возможность постепенного развития платформы без изменения архитектуры.
