# Раздел B — Бизнес-модель и процессы (Business Model & Processes)

## Назначение раздела

Раздел **B** содержит описание бизнес-сущностей, их жизненных циклов, событий, полномочий, бизнес-правил и автоматизации цифровой платформы **Simple Solutions Practice (SSP)**.

Документы этого раздела являются фундаментом для разработки:
- модели данных (раздел C);
- сервисного интерфейса (раздел C);
- принципов инжиниринга (раздел E).

Все программные компоненты, пользовательские интерфейсы, API и автоматические процессы обязаны соответствовать бизнес-модели, описанной в данном разделе.

---

## Перечень документов раздела

### 1. Business Object Model (BOM)

**Назначение:**  
Определяет состав бизнес-сущностей платформы, их атрибуты, жизненный цикл и взаимосвязи. Является единственным источником описания бизнес-логики.

**Содержание:**
- 15 бизнес-сущностей: Partner, Contact, Inquiry, Discovery Meeting, Proposal, Agreement, Cooperation Format, Project, Project Stage, Deliverable, Document, Payment, Event, Notification, Workspace.
- Схема жизненного цикла: от Partner до Deliverable.
- Архитектурные принципы (единственный источник истины, событийная модель, автоматизация без дублирования, разделение этапов).

---

### 2. B-002 Business State Model

**Назначение:**  
Определяет жизненный цикл каждой бизнес-сущности: допустимые состояния, правила переходов, инициаторов изменений и автоматические действия.

**Содержание:**
- Основные принципы (событие изменяет состояние, запрет прямого изменения статусов, необратимость истории).
- Стандарт описания объектов.
- Полные модели состояний для: Inquiry, Discovery Meeting, Proposal, Agreement, Project, Project Stage, Deliverable, Document, Payment, Notification, Workspace.
- Таблицы переходов с автоматическими действиями.
- Общие правила переходов и запрещённые действия.
- Архитектурные принципы.

---

### 3. B-003 Business Event Catalogue

**Назначение:**  
Определяет полный перечень бизнес-событий платформы. Каждое событие фиксирует факт изменения состояния бизнес-процесса и является единственным допустимым механизмом запуска автоматизации.

**Содержание:**
- Основные принципы (событие фиксирует факт, неизменяемость, один факт — одно событие).
- Классификация событий (Business, System, External).
- Стандарт описания события.
- Каталог событий по этапам жизненного цикла:
  - **Привлечение партнёра (EV-001…EV-009)** — Inquiry и Discovery Meeting.
  - **Согласование сотрудничества (EV-010…EV-020)** — Proposal и Agreement.
  - _Реализация проекта_ — Project, Stage, Deliverable.
  - _Финансовые операции_ — Invoice, Payment.
  - _Завершение сотрудничества_ — Project Completion, Archive.
- Правила обработки событий.
- Архитектурные принципы.

---

### 4. B-004 Permission Model

**Назначение:**  
Определяет полномочия участников платформы: какие бизнес-действия может выполнять каждая роль, а также правила проверки полномочий.

**Содержание:**
- Основные принципы (полномочия относятся к действиям, отсутствие права безопаснее ошибки, минимально необходимые полномочия).
- Роли платформы: Partner, Consultant, Administrator, System, External Service.
- Матрица полномочий (23 бизнес-действия × 5 ролей).
- Ограничения полномочий.
- Правила проверки (7 шагов).
- Архитектурные принципы.

---

### 5. B-005 Business Rules Catalogue

**Назначение:**  
Определяет обязательные правила принятия решений в платформе. Правила описывают условия допустимости выполнения действий.

**Содержание:**
- Основные принципы (правила определяет бизнес, правила проверяются до выполнения действия).
- Структура правила (код, название, объект, условие, ограничение, последствие, связанные события).
- Правила для всех объектов:
  - Inquiry (2 правила)
  - Proposal (3 правила)
  - Agreement (2 правила)
  - Project (3 правила)
  - Project Stage (3 правила)
  - Deliverable (3 правила)
  - Финансовые операции (4 правила)
  - Workspace (3 правила)
  - Документы (3 правила)
- Общие правила принятия решений (5 правил).
- Правила исключений.
- Архитектурные принципы.

---

### 6. B-006 Automation Blueprint

**Назначение:**  
Определяет принципы автоматической обработки бизнес-событий: архитектуру автоматизации, порядок выполнения действий и правила взаимодействия между бизнес-моделью и программной реализацией.

**Содержание:**
- Основные принципы автоматизации (8 принципов).
- **Automation Decision Pipeline** — единый порядок обработки любого Business Event (9 этапов).
- Каталог автоматических процессов (AP-001…AP-008):
  - Обработка Inquiry
  - Подготовка и отправка Proposal
  - Принятие Proposal (создание Agreement, Project, Workspace, Invoice)
  - Подтверждение оплаты
  - Завершение Stage
  - Завершение и архивирование Project
- Классификация процессов: Business Automation vs Infrastructure Automation.
- Правила выполнения (10 правил).
- Automation Reliability (механизмы обеспечения надёжности).
- Архитектурные принципы (7 принципов).
