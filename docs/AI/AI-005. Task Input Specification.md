# AI-005. Task Input Specification

## Purpose

Every development task must follow a standard structure.

AI agents must refuse tasks that do not contain sufficient information for safe implementation.

---

# Required Task Structure

Every task must contain the following sections.

---

## Task ID

Unique task identifier.

Example:

```
TASK-M104-001
```

---

## Objective

A short description of the required functionality.

Example:

```
Implement Check-up questionnaire persistence.
```

---

## Target Module

Exactly one module.

Examples:

```
M-101 Platform Kernel
M-104 Check-up
M-106 Workspace
```

A task must not target multiple modules unless explicitly stated.

---

## Related Documentation

List of Human Documentation that must be used.

Example:

```
M-104
E-004
R-002
```

The AI agent must not search for additional documents unless required by dependencies.

---

## Scope

Describe what the task includes.

Example:

```
Implement CRUD operations for Check-up Questions.
Persist data in PostgreSQL.
Expose public Capability.
```

---

## Out of Scope

Describe what must NOT be implemented.

Example:

```
No AI.

No Automation.

No Workflow.

No UI redesign.

No reporting.
```

---

## Files Allowed

List of files that may be modified.

Example:

```
backend/modules/checkup/*
backend/shared/*
```

---

## Files Protected

Files that must not be modified.

Example:

```
Platform Kernel

Other modules

Architecture documents
```

---

## Dependencies

List of required components.

Example:

```
Business Event

Repository

Capability

Artifact
```

---

## Definition of Done

Reference to the corresponding Human Documentation.

The AI agent must satisfy every documented requirement before completing the task.

---

# Validation

Before implementation begins, the AI agent must verify that:

* the target module is defined;
* required documentation exists;
* implementation belongs to the Pilot MVP;
* protected files are not affected.

If validation fails, implementation must not begin.

---

# Rule

One task.

One module.

One objective.

One completed result.
