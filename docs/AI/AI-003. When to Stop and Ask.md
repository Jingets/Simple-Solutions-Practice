# AI-003. When to Stop and Ask

## Purpose

An AI developer must never invent missing architecture.

When documentation is insufficient, implementation must stop.

---

# Stop Immediately If

## Documentation is Missing

The required behaviour is not described in the Human Documentation.

Do not infer the missing behaviour.

Request clarification.

---

## Documents Conflict

Two or more documents define different behaviour.

Do not choose one version.

Report the conflict.

---

## Architecture Must Change

The requested implementation requires:

* new Platform services;
* new module responsibilities;
* new Business Events;
* new Capability contracts;
* changes to Platform Kernel.

Do not implement.

Request an architecture update.

---

## Business Logic is Undefined

The business rule cannot be derived from documentation.

Do not invent business behaviour.

Request clarification.

---

## The Request Extends the MVP

The requested functionality is outside the documented Pilot MVP.

Examples:

* automation;
* AI assistants;
* workflow orchestration;
* optimization;
* scalability;
* multi-user support.

Stop implementation.

---

## Existing Architecture Can Be Reused

Never create a new abstraction before checking existing modules.

Prefer reuse over expansion.

---

# Never Assume

Never assume:

* business rules;
* user intentions;
* process order;
* validation rules;
* lifecycle transitions.

Everything must be documented.

---

# Required Response

If implementation cannot continue, report:

1. what information is missing;
2. which document should define it;
3. why implementation cannot continue safely.

Do not continue coding after reporting the issue.
