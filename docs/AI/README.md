# Раздел AI — Инструкции для AI-разработчиков (AI Developer Instructions)

## Назначение раздела

Раздел **AI** содержит инструкции для AI-агентов (или разработчиков, работающих в среде "вайб-кодинга"), которые будут реализовывать **Pilot MVP** платформы **Simple Solutions Practice (SSP)**.

Документы этого раздела **не являются архитектурной документацией**. Они являются **инструкцией по ограничению объёма работ** для тех, кто склонен "докручивать" и расширять функциональность.

Документы определяют:
- миссию и границы Pilot MVP;
- как читать документацию SSP;
- как выполнять задачи (пошаговый процесс);
- когда останавливаться и запрашивать уточнения;
- структуру входных и выходных данных задачи;
- обязательные ограничения разработки.

---

## Перечень документов раздела

### 1. AI-000. Read Me First

**Назначение:**  
Определяет миссию AI-разработчика, границы Pilot MVP, критерии успеха и то, что **не нужно** реализовывать.

**Содержание:**
- Миссия (разработать один полный консультационный процесс: Lead → Check-up → Proposal → Offer → Workspace → Certificate)
- Критерий успеха (один консультант, один клиент, один проект, финальная документация)
- Что **не** реализовывать (полномасштабные версии Automation Engine, AI Agents, Workflow Engine, Organizational Memory, Multi-user, Complex UI, Performance optimizations)
- **Исключение:** минимальный Event Dispatcher и Workflow Dispatcher (согласно M-101) **разрешены**, так как они необходимы для регистрации Business Events и управления статусами проекта.
- Доверие к Human Documentation
- Следование существующей архитектуре
- Построение простейшего рабочего решения
- Остановка после завершения MVP

---

### 2. AI-001. How to Read SSP Documentation

**Назначение:**  
Определяет, как читать документацию SSP: приоритет разделов, где искать информацию, стратегию чтения и действия при пропущенной информации.

**Содержание:**
- Приоритет документации: **M → E → R → B → X → C → A**
- Где искать информацию (по разделам)
- Стратегия чтения (читать только необходимое)
- Действия при пропущенной информации (не изобретать, запросить уточнение)
- Запрет на изменение архитектуры AI-агентами

---

### 3. AI-002. How to Execute Development Tasks

**Назначение:**  
Определяет единый процесс выполнения любой задачи: от понимания до остановки.

**Содержание:**
- Шаг 1. Понять задачу
- Шаг 2. Найти модуль (в разделе M)
- Шаг 3. Прочитать поддерживающую документацию
- Шаг 4. Проверить scope (принадлежность к Pilot MVP)
- Шаг 5. Реализовать (только документированное поведение)
- Шаг 6. Проверить (Definition of Done)
- Шаг 7. Остановиться

---

### 4. AI-003. When to Stop and Ask

**Назначение:**  
Определяет ситуации, в которых реализация должна быть остановлена и запрошено уточнение.

**Содержание:**
- Остановка при: пропущенной документации, конфликте документов, необходимости изменения архитектуры, неопределённой бизнес-логике, запросе вне MVP
- Запрет на предположения (бизнес-правила, намерения пользователя, порядок процессов, валидация, переходы жизненного цикла)
- Требуемый ответ при остановке (что отсутствует, какой документ должен это определить, почему нельзя продолжать)

---

### 5. AI-004. Deliverables

**Назначение:**  
Определяет, что должно быть результатом завершённой задачи.

**Содержание:**
- Обязательные артефакты (исходный код, тесты, документация, подтверждение Definition of Done)
- Требования к исходному коду (без экспериментального кода, заглушек, закомментированного кода)
- Требования к тестам (верификация поведения, бизнес-правил, границ модуля)
- Требования к документации (обновление при изменении поведения)
- Отчёт о завершении (краткий отчёт с перечнем изменений)
- Запрет на частичную сдачу работы

---

### 6. AI-005. Task Input Specification

**Назначение:**  
Определяет структуру входных данных для задачи, которую получает AI-разработчик.

**Содержание:**
- Обязательные разделы: Task ID, Objective, Target Module, Related Documentation, Scope, Out of Scope, Files Allowed, Files Protected, Dependencies, Definition of Done
- Пример заполнения
- Валидация перед началом реализации
- Правило: одна задача → один модуль → одна цель → один завершённый результат

---

### 7. AI-006. Task Output Specification

**Назначение:**  
Определяет структуру отчёта о завершённой задаче.

**Содержание:**
- Обязательные разделы: Task, Status, Summary, Modified Files, Created Files, Deleted Files, Tests, Documentation, Definition of Done, Known Limitations, Notes, Blockers
- Запрещённые разделы (идеи функций, предложения по оптимизации, перепроектирование архитектуры)
- Правило завершения: задача завершена только при выполнении всех требований

---

### 8. AI-007. Development Constraints

**Назначение:**  
Определяет обязательные ограничения разработки для всех AI-агентов.

**Содержание:**
- Только Pilot MVP (без функциональности будущих версий)
- Архитектура неизменна (без новых модулей, сервисов, событий, Artifact-типов, Capability-контрактов)
- Границы модулей (изменять только целевой модуль)
- Защита Platform Kernel (не изменять без явного указания)
- Без скрытой функциональности (без "на будущее")
- Без преждевременной автоматизации (исключение: минимальный Event Dispatcher и Workflow Dispatcher из M-101)
- Без преждевременной оптимизации
- Без незапрошенного рефакторинга
- Документация прежде кода
- Единый источник истины — Human Documentation
- Одна задача — один результат
- При неопределённости — остановиться и запросить уточнение

## Связи с другими разделами

| Раздел | Связь |
|--------|-------|
| **M — MVP** | AI-инструкции ссылаются на M-101 (Platform Kernel) и M-106 (Project Execution) |
| **E — Инжиниринг** | AI-инструкции ссылаются на E (архитектура) при необходимости |

| **C — Техническая архитектура** | AI-инструкции ссылаются на C (модели хранения, API) при необходимости |
| **A — Архитектурные принципы** | AI-инструкции ссылаются на A (общие принципы) |

## Важное примечание

Документы раздела AI **не заменяют** архитектурную документацию (разделы A, B, C, E, M, R, X). Они являются **инструкцией по её использованию**.

**Ключевое исключение:** запрет на Workflow Engine и Automation Engine в AI-000 **не распространяется** на минимальные реализации, требуемые M-101 (Platform Kernel):
- **Event Dispatcher** — для регистрации Business Events;
- **Workflow Dispatcher** — для управления статусами проекта (LINEAR и CONDITIONAL workflows).

Эти компоненты **обязательны** для MVP и должны быть реализованы в минимальном объёме, достаточном для выполнения одного полного консультационного цикла.
