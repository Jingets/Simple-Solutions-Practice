# AI-000. Read Me First #

## Your Mission ##

You are not developing the entire SSP platform.

You are developing the Pilot MVP.

The Pilot MVP consists of one complete consulting process:

Lead

↓

Check-up

↓

Proposal

↓

Offer

↓

Workspace

↓

Certificate

Your task is to make this process work completely.

Nothing more.

---

## What Success Means ##

The Pilot MVP is complete when:

* one consultant can execute the entire process;
* the consultant is authenticated and authorised (basic JWT-based auth as defined in X-008, Stage 4).
* one client can pass through the entire process;
* one project can be completed;
* the client receives the final documentation.

Everything else is out of scope.

---

## Do Not Build ##

Do not implement:

* General-purpose Automation Engine. Implement only Event Dispatcher that registers Business Events and triggers simple workflows (as defined in M-101 and X-004).
* AI Agents
* Full-featured Workflow Engine (parallel execution, compensation, versioning, persistence). Implement only the minimal Workflow Dispatcher required for MVP status transitions (LINEAR and CONDITIONAL as defined in M-101).
* Organizational Memory
* Multi-user support
* Complex UI
* Performance optimizations
* Generic infrastructure for future use

If a feature is not required to complete the Pilot MVP, do not implement it.

---

## Trust the Documentation ##

The Human Documentation is the single source of truth.

Never invent architecture.

Never introduce new business concepts.

Never create new module responsibilities.

If documentation is unclear, request clarification instead of making assumptions.

---

## Follow Existing Architecture ##

Business logic belongs to modules.

Modules communicate only through Platform Kernel.

Business state changes only through Business Events.

Public interaction with a module occurs only through its Capability.

Do not violate these principles.

---

## Build the Simplest Working Solution ##

Prefer the simplest implementation that satisfies the documented behaviour.

Do not optimize for future requirements.

Do not create extension points that are not currently needed.

---

## Stop When the MVP Works ##

The goal is not to build the final platform.

The goal is to finish one complete working consulting process.

After that, development stops until the architecture evolves.
