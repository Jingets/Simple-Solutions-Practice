# AI-004. Deliverables

## Purpose

Every completed task must produce a complete and verifiable result.

A task is not finished when the code compiles.

A task is finished when all required deliverables are complete.

---

# Required Deliverables

Every implementation task must produce:

* updated source code;
* updated automated tests;
* updated documentation (if required);
* confirmation that the Definition of Done has been satisfied.

---

# Source Code

Implement only the documented behaviour.

Do not include:

* experimental features;
* placeholder implementations;
* commented-out code;
* unused abstractions.

---

# Tests

Every implemented behaviour must be verified.

Tests must validate:

* expected behaviour;
* business rules;
* module boundaries;
* public Capability interface.

---

# Documentation

If implementation changes documented behaviour, the Human Documentation must be updated before the task is considered complete.

If behaviour remains unchanged, documentation updates are not required.

---

# Definition of Done

The corresponding module document defines the Definition of Done.

Implementation is complete only when every requirement has been satisfied.

---

# Completion Report

At the end of every task, provide a short report containing:

* implemented functionality;
* modified files;
* executed tests;
* documentation updates;
* unresolved issues (if any).

---

# Never Deliver Partial Work

Do not report a task as completed if:

* required tests are missing;
* documented behaviour is incomplete;
* Definition of Done is not satisfied.

If work cannot be completed, report the reason instead of declaring success.
