# AI-006. Task Output Specification

## Purpose

Every completed development task must produce a standard completion report.

The report allows a human reviewer to verify the implementation without analysing the entire codebase.

---

# Required Output

Every completed task must contain the following sections.

---

## Task

Task ID.

Example:

```text
TASK-M104-001
```

---

## Status

One of:

```text
Completed

Partially Completed

Blocked
```

---

## Summary

Brief description of the implemented functionality.

Maximum five sentences.

---

## Modified Files

List every modified file.

Example:

```text
backend/modules/checkup/service.py

backend/modules/checkup/capability.py

backend/modules/checkup/repository.py
```

---

## Created Files

List every newly created file.

If none:

```text
None
```

---

## Deleted Files

List every deleted file.

If none:

```text
None
```

---

## Tests

List all implemented or modified tests.

If tests were not created, explain why.

---

## Documentation

Specify whether Human Documentation was updated.

Possible values:

```text
Updated

Not Required

Requires Update
```

---

## Definition of Done

State whether every documented requirement has been satisfied.

Possible values:

```text
Satisfied

Not Satisfied
```

If not satisfied, explain which requirement remains incomplete.

---

## Known Limitations

Describe only limitations that are already documented.

Do not invent future improvements.

---

## Notes

Optional implementation notes for the reviewer.

Do not include architecture proposals.

---

# Prohibited Output

Do not include:

* feature ideas;
* optimization suggestions;
* architecture redesign;
* future roadmap;
* unrelated refactoring proposals.

The report must describe only the completed task.

---

# Completion Rule

A task is complete only when:

* implementation is finished;
* tests are complete;
* Definition of Done is satisfied;
* completion report is generated.
