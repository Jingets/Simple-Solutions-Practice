# AI-007. Development Constraints

## Purpose

This document defines mandatory development constraints for all AI agents working on the SSP Pilot MVP.

These rules override implementation preferences.

---

# Pilot MVP Only

Develop only the documented Pilot MVP.

Do not implement functionality planned for future platform versions.

---

# Architecture Is Immutable

Do not modify the documented platform architecture.

Do not introduce:

* new modules;
* new platform services;
* new Business Events;
* new Artifact types;
* new Capability contracts.

Architecture changes require documentation updates before implementation.

---

# Module Boundaries

Modify only the target module specified by the task.

Do not change neighbouring modules unless explicitly requested.

---

# Kernel Protection

Do not modify Platform Kernel unless the task explicitly targets the Kernel.

Do not move business logic into the Kernel.

---

# No Hidden Functionality

Do not implement undocumented behaviour.

Do not create features "for future use".

Do not add extension points that are not currently required.

---

# No Premature Automation

Do not implement:

* Automation Engine;
* Workflow Engine;
* AI Agents;
* Organizational Memory;
* background jobs;
* scheduled tasks.

These components are outside the Pilot MVP.

---

# No Premature Optimization

Do not optimize:

* performance;
* scalability;
* database structure;
* caching;
* concurrency.

The objective is a correct working implementation.

---

# No Unrequested Refactoring

Do not refactor unrelated code.

Do not rename files, classes or modules unless explicitly required.

Do not reorganize project structure.

---

# Documentation First

If implementation requires changing documented behaviour:

Stop.

Request documentation update before continuing.

---

# Single Source of Truth

The Human Documentation is authoritative.

If source code and documentation differ, follow the documentation and report the inconsistency.

---

# One Task — One Result

Complete only the assigned task.

Do not continue with adjacent improvements after the task is finished.

Stop immediately after satisfying the documented Definition of Done.

---

# Final Rule

When uncertain:

Stop.

Read the documentation again.

If uncertainty remains, report the issue instead of making assumptions.
