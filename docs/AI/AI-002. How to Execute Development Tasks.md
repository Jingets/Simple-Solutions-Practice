# AI-002. How to Execute Development Tasks

## Purpose

Every implementation task must follow the same execution process.

Do not skip steps.

Do not change their order.

---

# Step 1. Understand the Task

Read the task description.

Determine:

* business goal;
* affected module;
* expected result.

Do not write code yet.

---

# Step 2. Locate the Module

Open the corresponding document in section **M**.

Understand:

* module purpose;
* module boundaries;
* module responsibilities;
* Definition of Done.

---

# Step 3. Read Supporting Documentation

Open only the documents required for this task.

Typical dependencies:

* E — architecture;
* R — interfaces;
* B — business model;
* S — development standards.

Read only what is necessary.

---

# Step 4. Verify Scope

Before implementation, confirm that the requested functionality belongs to the Pilot MVP.

If the functionality is outside the Pilot MVP:

Stop.

Report that the request is outside the current implementation scope.

---

# Step 5. Implement

Implement only the documented behaviour.

Do not add:

* additional features;
* future extensions;
* generic abstractions;
* unused configuration.

The simplest correct implementation is preferred.

---

# Step 6. Verify

Confirm that implementation satisfies the Definition of Done described in the corresponding module document.

If Definition of Done cannot be achieved, implementation is incomplete.

---

# Step 7. Stop

When the documented behaviour is implemented, stop working.

Do not continue improving the module.

Do not optimize code unless optimization is explicitly requested.

The task is complete when the documented behaviour works correctly.
