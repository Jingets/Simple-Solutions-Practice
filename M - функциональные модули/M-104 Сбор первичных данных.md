**M-104 Сбор первичных данных**

**Статус:** MVP

**Приоритет:** P0 (обязательный)

**Цель**

Реализовать модуль проведения операционного Check-up организации.

После выполнения задания платформа должна обеспечивать проведение диагностики бизнеса, анализ полученной информации, определение объёма проекта и расчёт стоимости работ.

Результатом работы модуля является готовая оценка проекта, используемая для формирования договора-оферты.

**Контекст**

Check-up является основной услугой первой версии SSP.

Модуль объединяет полный цикл первичной диагностики клиента:

- сбор информации;

- анализ результатов;

- определение состава работ;

- расчёт стоимости проекта.

Модуль завершается подготовкой **Estimation Report**.

**Технический стек**

**Backend**

- Python 3.13

- FastAPI

- SQLAlchemy

- PostgreSQL

**Frontend**

- React

- TypeScript

- Vite

**Capability**

Модуль реализует две независимые Capability.

**Capability 1 — Diagnostic Interview**

**Назначение**

Проведение структурированной диагностики организации.

**Необходимо реализовать**

Консультант должен иметь возможность:

- открыть Check-up;

- проходить диагностику по тематическим блокам;

- сохранять ответы автоматически;

- прерывать диагностику;

- продолжать её позднее.

**Минимальный состав разделов**

- сведения о компании;

- организационная структура;

- основные бизнес-процессы;

- используемые информационные системы;

- финансовое управление;

- операционное управление;

- основные проблемы;

- цели проекта.

**Результат**

Создаётся Artifact:

**Check-up Report**

Создаётся Business Event:

**CheckupCompleted**

**Capability 2 — Project Estimation**

**Назначение**

Подготовка экспертной оценки проекта на основании результатов Check-up.

**Необходимо реализовать**

Консультант должен иметь возможность:

- определить перечень необходимых работ;

- определить объём проекта;

- определить ориентировочную трудоёмкость;

- определить стоимость проекта;

- определить предполагаемые сроки выполнения;

- добавить комментарии и пояснения.

**Результат**

Создаётся Artifact:

**Estimation Report**

Estimation Report должен содержать:

- выявленные проблемы;

- рекомендуемый состав работ;

- объём проекта;

- стоимость;

- сроки выполнения;

- комментарии консультанта.

Создаётся Business Event:

**ProjectEstimated**

**Не реализовывать**

Не входят в MVP:

- автоматическую AI-оценку;

- автоматический расчёт стоимости;

- отраслевые шаблоны оценки;

- машинное обучение;

- прогнозирование рисков;

- автоматическое определение состава работ.

Все решения принимаются консультантом.

Платформа обеспечивает удобную фиксацию и хранение результатов.

**Архитектурные ограничения**

Модуль Check-up:

- не формирует договор;

- не запускает выполнение проекта;

- не изменяет Workflow;

- завершает этап диагностики подготовкой Estimation Report.

**Definition of Done**

Модуль считается готовым, если:

- диагностика успешно проводится;

- ответы автоматически сохраняются;

- формируется Check-up Report;

- консультант может подготовить экспертную оценку проекта;

- формируется Estimation Report;

- создаются Business Event CheckupCompleted и ProjectEstimated;

- оба документа сохраняются в Project Workspace.

**Результат**

После выполнения задания SSP получает возможность провести полный цикл диагностики организации и подготовить экспертную оценку проекта, содержащую объём работ, стоимость и сроки выполнения.

Estimation Report является единственным источником данных для формирования договора-оферты.
