**M-106 Сопровождение выполнения проекта**

**Статус:** MVP

**Приоритет:** P0 (обязательный)

**Цель**

Реализовать модуль сопровождения выполнения консалтингового проекта.

После выполнения задания платформа должна обеспечивать контроль жизненного цикла проекта, фиксацию результатов выполнения работ и накопление материалов проекта до момента его завершения.

**Контекст**

Project Execution начинается автоматически после регистрации Business Event:

**OfferAccepted**

Модуль сопровождает выполнение проекта до подготовки акта выполненных работ.

Модуль не занимается управлением задачами сотрудников и не является системой управления проектами общего назначения.

**Технический стек**

**Backend**

- Python 3.13

- FastAPI

- SQLAlchemy

- PostgreSQL

**Frontend**

- React

- TypeScript

- Vite

**Необходимо реализовать**

**Управление состоянием проекта**

Поддерживать состояния проекта:

- In Progress

- On Hold

- Waiting Client

- Review

- Completed

Изменение состояния фиксируется в истории проекта.

**Рабочий журнал**

Консультант должен иметь возможность фиксировать:

- выполненные действия;

- встречи;

- консультации;

- полученные документы;

- промежуточные результаты;

- важные замечания.

Каждая запись автоматически получает дату и автора.

**Хранение материалов**

Project Workspace должен обеспечивать хранение:

- документов;

- таблиц;

- презентаций;

- изображений;

- иных Artifact проекта.

**Промежуточные результаты**

Консультант должен иметь возможность сохранять результаты отдельных этапов проекта.

Каждый результат сохраняется как Artifact.

**История проекта**

Все действия автоматически регистрируются в Project Workspace.

История проекта должна быть полностью воспроизводимой.

**Business Event**

При завершении выполнения проекта создать Business Event:

**ProjectCompleted**

**Не реализовывать**

Не входят в MVP:

- управление задачами сотрудников;

- диаграммы Ганта;

- Kanban-доски;

- календарное планирование;

- совместное редактирование документов;

- внутренний чат;

- уведомления;

- контроль рабочего времени.

**Архитектурные ограничения**

Project Execution:

- не принимает управленческих решений;

- не изменяет результаты Check-up;

- не изменяет Estimation Report;

- не изменяет договор-оферту;

- сопровождает выполнение проекта и фиксирует результаты работ.

**Definition of Done**

Модуль считается готовым, если:

- проект автоматически переходит в состояние In Progress после оплаты договора-оферты;

- консультант может вести рабочий журнал проекта;

- промежуточные результаты сохраняются как Artifact;

- история проекта полностью сохраняется;

- возможно перевести проект в состояние Completed;

- создаётся Business Event ProjectCompleted.

**Результат**

После выполнения задания SSP получает возможность сопровождать выполнение консалтингового проекта, фиксировать результаты работ и сохранять всю историю проекта до его завершения.
