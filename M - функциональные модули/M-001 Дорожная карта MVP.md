**M-001 Дорожная карта MVP**

**Версия:** 1.0

**Статус:** Draft

**Раздел:** M — MVP Delivery

**1. Цель MVP**

Первая версия Simple Solutions Practice должна обеспечивать полный цикл оказания консалтинговой услуги от получения заявки до формирования закрывающих документов.

MVP создаётся для проверки бизнес-модели, получения первых платящих клиентов и накопления организационного опыта.

Архитектура платформы должна оставаться расширяемой, однако реализуется только минимально необходимая функциональность.

**2. Критерий готовности MVP**

MVP считается завершённым, если платформа позволяет выполнить следующий бизнес-процесс:

1.  Получение заявки.

2.  Первичная квалификация клиента.

3.  Проведение Check-up.

4.  Расчёт стоимости работ.

5.  Формирование коммерческого предложения.

6.  Подготовка договора-оферты.

7.  Выполнение работ.

8.  Формирование акта выполненных работ.

9.  Архивация результатов проекта.

**3. Принципы разработки MVP**

**MVP-001**

Реализуется только функциональность, необходимая для оказания услуги.

**MVP-002**

Каждый модуль должен использовать существующую архитектуру Platform Kernel.

**MVP-003**

Функции, не влияющие на оказание первой услуги, откладываются.

**MVP-004**

Архитектура проектируется с расчётом на развитие, но код реализуется только в объёме текущих бизнес-задач.

**MVP-005**

Каждый завершённый проект должен увеличивать Organizational Memory платформы.

**Архитектурное правило**

Сначала работающий бизнес.

Потом масштабирование платформы.

**4. Состав первой версии**

В MVP входят только следующие основные модули:

**Core Platform**

- Platform Kernel

- Workflow Engine

- Artifact Storage

- Organizational Memory

**Business Modules**

- Lead Intake

- Check-up

- Proposal Generator

- Offer Generator

- Project Workspace

- Act Generator

**Support Modules**

- Document Templates

- Reporting

- User Management

**5. Что НЕ входит в MVP**

В первую версию платформы сознательно не входят:

- Marketplace модулей;

- автоматическая генерация кода;

- интеграция с API LLM;

- специализированные Domain;

- несколько Cognitive Worker;

- сложная система Policy;

- распределённая Organizational Memory;

- внешние SDK;

- публичный API платформы;

- автоматическое построение модулей.

Указанные возможности относятся к следующим этапам развития платформы.

**Статус документа**

Документ определяет минимальный объём реализации, необходимый для запуска коммерческой эксплуатации первой версии Simple Solutions Practice.
