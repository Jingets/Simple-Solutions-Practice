**E-016 Спецификация возможностей**

**Версия:** 1.0

**Статус:** Draft

**Раздел:** E — Engineering Architecture

**1. Scope**

Настоящий документ определяет архитектурную модель Capability платформы Simple Solutions Practice.

Capability является минимальной единицей функциональности платформы.

Platform Kernel взаимодействует исключительно с Capability Contract.

**2. Capability**

Capability представляет собой декларативно описанную возможность платформы выполнить определённую бизнес-функцию.

Capability не определяет способ реализации.

Capability определяет только архитектурный контракт.

**CAP-001**

Каждая Capability имеет уникальный идентификатор.

**CAP-002**

Каждая Capability имеет собственный Capability Contract.

**CAP-003**

Каждая Capability может иметь одну или несколько реализаций.

**CAP-004**

Platform Kernel взаимодействует с Capability, а не с модулем.

**CAP-005**

Capability публикуется Module через Module Manifest.

**Архитектурное правило**

Capability описывает возможность.

Module реализует возможность.

**3. Capability Contract**

Capability Contract определяет правила взаимодействия между Platform Kernel и реализацией Capability.

**CC-001**

Capability Contract является стабильным.

**CC-002**

Изменение реализации Capability не изменяет Capability Contract.

**CC-003**

Capability Contract определяет входной Module Context.

**CC-004**

Capability Contract определяет результат выполнения.

**CC-005**

Capability Contract не зависит от языка программирования, технологии реализации или внутренней архитектуры модуля.

**Архитектурное правило**

Kernel взаимодействует с контрактом.

Не с реализацией.

**4. Capability Lifecycle**

Каждая Capability проходит единый архитектурный жизненный цикл.

Жизненный цикл определяется Platform Kernel.

**CL-001**

Discovery

Capability обнаружена Platform Kernel.

**CL-002**

Registration

Capability зарегистрирована в Platform Kernel.

**CL-003**

Validation

Capability Contract успешно проверен.

**CL-004**

Available

Capability доступна для выполнения.

**CL-005**

Execution

Capability выполняет полученный Execution Request.

**CL-006**

Completed

Выполнение успешно завершено.

**CL-007**

Unavailable

Capability временно исключена из процесса выполнения.

**Архитектурное правило**

Platform Kernel управляет жизненным циклом Capability.

**5. Capability Invocation**

Capability вызывается исключительно Platform Kernel.

Никакие другие архитектурные компоненты не взаимодействуют с Capability напрямую.

**CI-001**

Execution Request формируется Platform Kernel.

**CI-002**

Platform Kernel передаёт Capability подготовленный Module Context.

**CI-003**

Capability не изменяет полученный Module Context.

**CI-004**

Capability возвращает только результат выполнения.

**CI-005**

Capability не инициирует выполнение других Capability самостоятельно.

**Архитектурное правило**

Capability ничего не знает об окружающей платформе.

**6. Capability Result**

Каждое выполнение Capability завершается формированием Capability Result.

Capability Result является единственным допустимым результатом выполнения Capability.

**CR-001**

Capability Result содержит статус выполнения.

**CR-002**

Capability Result содержит созданные Artifact.

**CR-003**

Capability Result содержит зарегистрированные Business Event и System Event, если они возникли в результате выполнения.

**CR-004**

Capability Result может содержать диагностическую информацию.

**CR-005**

Capability Result не содержит внутренних структур реализации Capability.

**Архитектурное правило**

Platform Kernel анализирует только Capability Result.

**7. Capability Atomicity**

Каждое выполнение Capability является неделимой архитектурной операцией.

Capability либо успешно завершает выполнение, либо считается невыполненной.

**CAT-001**

Capability не допускает частичного успешного выполнения.

**CAT-002**

При невозможности завершения выполнения Platform Kernel получает информацию о неуспешном результате.

**CAT-003**

Все созданные Business Event, System Event и Artifact относятся к одному выполнению Capability.

**CAT-004**

Platform Kernel определяет дальнейшие действия после завершения Capability.

**CAT-005**

Capability не принимает решений о повторном выполнении самостоятельно.

**Архитектурное правило**

Capability выполняется как единая бизнес-операция.

**8. Capability Independence**

Каждая Capability должна быть независимой от остальных Capability.

**CPI-001**

Capability не знает о существовании других Capability.

**CPI-002**

Capability не инициирует выполнение других Capability.

**CPI-003**

Capability не зависит от порядка выполнения других Capability.

**CPI-004**

Capability не хранит внутреннее состояние между выполнениями.

**CPI-005**

Каждое выполнение Capability является полностью самостоятельным.

**Архитектурное правило**

Capability является независимой единицей выполнения.

**9. Capability Determinism**

При одинаковом Module Context Capability должна формировать одинаковый результат.

**CDT-001**

Результат определяется входным контекстом.

**CDT-002**

Capability не использует скрытые источники данных.

**CDT-003**

Все внешние зависимости предоставляются через Platform Kernel.

**CDT-004**

Повторное выполнение с одинаковым Context должно быть воспроизводимым.

**CDT-005**

Platform Kernel обеспечивает воспроизводимость выполнения.

**Архитектурное правило**

Одинаковый Context должен приводить к одинаковому результату.

**10. Capability Versioning**

Capability Contract развивается эволюционно.

Изменение реализации Capability не должно нарушать совместимость существующих архитектурных контрактов.

**CV-001**

Каждая Capability имеет собственную версию Capability Contract.

**CV-002**

Изменение внутренней реализации не требует изменения версии Capability Contract.

**CV-003**

Несовместимые изменения требуют публикации новой версии Capability Contract.

**CV-004**

Platform Kernel определяет совместимость Capability Contract во время регистрации.

**CV-005**

Platform Kernel не использует Capability Contract, признанный несовместимым.

**Архитектурное правило**

Совместимость определяется контрактом.

Не реализацией.

**11. Capability Registry**

Platform Kernel поддерживает единый реестр всех зарегистрированных Capability.

Capability Registry является частью Module Catalog.

**CRG-001**

Каждая зарегистрированная Capability публикуется в Capability Registry.

**CRG-002**

Capability Registry содержит Capability Contract и сведения о доступных реализациях.

**CRG-003**

Platform Kernel использует Capability Registry при разрешении Execution Request.

**CRG-004**

Capability Registry автоматически обновляется при регистрации, обновлении и удалении модулей.

**CRG-005**

Capability Registry является единственным источником информации о доступных Capability.

**Архитектурное правило**

Platform Kernel работает с Registry.

Не с реализациями.

**12. Architectural Principles**

Capability является базовой единицей функциональности платформы.

Platform Kernel взаимодействует исключительно с Capability Contract.

Capability выполняет только собственную бизнес-функцию.

Все архитектурные решения принимаются вне Capability.

**AP-001**

Capability реализует одну законченную бизнес-операцию.

**AP-002**

Capability не принимает архитектурных решений.

**AP-003**

Capability не инициирует выполнение других Capability.

**AP-004**

Capability работает только с предоставленным Module Context.

**AP-005**

Capability возвращает только Capability Result.

**Архитектурное правило**

Capability исполняет.

Platform Kernel оркестрирует.

Настоящий документ определяет Capability как минимальную архитектурную единицу функциональности платформы Simple Solutions Practice. Все возможности платформы публикуются посредством Capability Contract, реализуются независимыми модулями и оркестрируются Platform Kernel. Capability являются стабильной архитектурной границей между ядром платформы и её расширяемой функциональностью.
