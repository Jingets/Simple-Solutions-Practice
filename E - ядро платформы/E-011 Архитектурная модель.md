**E-011 Архитектурная модель**

**Версия:** 1.0

**Статус:** Draft

**Раздел:** E — Engineering Architecture

**1. Scope**

Настоящий документ определяет архитектурную модель Artifact платформы Simple Solutions Practice.

Artifact является основной единицей результата деятельности платформы.

Любая завершённая работа должна приводить к созданию, изменению либо использованию одного или нескольких Artifact.

**2. Artifact Principles**

Artifact представляет собой самостоятельный Platform Object.

Artifact существует независимо от способа его создания.

**AP-001**

Artifact является результатом завершённой деятельности.

**AP-002**

Artifact обладает собственной идентичностью.

**AP-003**

Artifact имеет самостоятельный жизненный цикл.

**AP-004**

Artifact может использоваться повторно различными Workflow.

**AP-005**

Artifact не зависит от технологии хранения и способа представления.

**Архитектурное правило**

Workflow выполняет работу.

Artifact сохраняет её результат.

**3. Artifact Definition**

Artifact представляет собой логическую бизнес-сущность, содержащую результат выполненной деятельности.

Artifact может быть создан:

- Human Worker;

- Cognitive Worker;

- Workflow;

- External System;

- Platform Kernel.

Источник создания не влияет на архитектурную природу Artifact.

**Архитектурное правило**

Источник создания не определяет тип Artifact.

Определяющим является его бизнес-назначение.

**4. Artifact Identity**

Каждый Artifact обладает собственной неизменяемой идентичностью.

**AI-001**

Identity создаётся одновременно с Artifact.

**AI-002**

Identity никогда не изменяется.

**AI-003**

Все ссылки выполняются посредством Identity.

**AI-004**

Удаление Artifact не приводит к повторному использованию Identity.

**AI-005**

Identity не зависит от имени, формата или версии Artifact.

**Архитектурное правило**

Identity определяет Artifact.

Не его представление.

**9. Artifact Model**

Архитектурная модель Artifact разделяет бизнес-сущность, способы её представления и физическое хранение.

Каждый уровень модели обладает собственной областью ответственности.

**AM-001**

Artifact представляет собой логический результат выполненной деятельности.

**AM-002**

Representation представляет собой способ отображения Artifact.

**AM-003**

Storage Object представляет собой физическое размещение Representation.

**AM-004**

Изменение Representation не изменяет Artifact.

**AM-005**

Изменение Storage Object не изменяет Artifact и его Representation.

**Архитектурное правило**

Бизнес-сущность, представление и хранение являются независимыми уровнями архитектуры.

**10. Physical Storage**

Platform Kernel не зависит от технологии хранения Artifact.

Физическое хранение является инфраструктурной задачей.

**PS-001**

Storage Object не является Platform Object.

**PS-002**

Platform Kernel взаимодействует только с архитектурными сервисами хранения.

**PS-003**

Технология хранения может изменяться без изменения архитектурной модели платформы.

**PS-004**

Несколько Storage Object могут хранить одно Representation.

**PS-005**

Перенос Representation между различными системами хранения не изменяет Artifact.

**Архитектурное правило**

Платформа управляет Artifact.

Инфраструктура управляет хранением.

**11. Artifact Relationships**

Artifact может быть связан с другими Platform Objects.

Связи определяют бизнес-контекст использования Artifact.

**RL-001**

Artifact может быть связан с одним или несколькими Workflow.

**RL-002**

Artifact может быть связан с одним или несколькими Task.

**RL-003**

Artifact может быть связан с одним или несколькими Business Objects.

**RL-004**

Artifact может использоваться несколькими Worker одновременно.

**RL-005**

Связи между Artifact журналируются Platform Kernel.

**Архитектурное правило**

Artifact существует самостоятельно.

Связи определяют контекст его использования.

**12. Artifact Ownership**

Каждый Artifact имеет владельца.

Владение Artifact определяется бизнес-моделью платформы.

**AO-001**

Owner назначается при создании Artifact.

**AO-002**

Owner отвечает за актуальность Artifact.

**AO-003**

Исполнитель создания Artifact может отличаться от его Owner.

**AO-004**

Изменение Owner фиксируется Platform Kernel.

**AO-005**

История изменения владельца сохраняется в Audit Service.

**Архитектурное правило**

Создатель, исполнитель и владелец Artifact могут быть различными субъектами.

**13. Artifact Preservation**

Artifact является долговременным результатом деятельности платформы.

Политика хранения определяется требованиями предметной области и нормативными ограничениями.

**APV-001**

Artifact не удаляется после завершения Workflow.

**APV-002**

История версий Artifact сохраняется в соответствии с политикой хранения.

**APV-003**

Архивирование Artifact не изменяет его идентичность.

**APV-004**

Удаление Artifact допускается только в случаях, предусмотренных политикой платформы.

**APV-005**

Каждый Artifact сохраняет возможность последующего использования до окончания срока хранения.

**Архитектурное правило**

Workflow завершается.

Artifact продолжает существовать.

**14. Artifact Reuse**

Artifact создаётся с расчётом на его последующее использование.

Повторное использование является одной из основных целей существования Artifact.

**RU-001**

Artifact может использоваться в нескольких независимых Workflow.

**RU-002**

Artifact может использоваться различными Human Worker и Cognitive Worker.

**RU-003**

Artifact может служить исходным материалом для создания новых Artifact.

**RU-004**

Artifact может использоваться при автоматическом принятии решений платформой.

**RU-005**

Повторное использование Artifact не изменяет его идентичность.

**Архитектурное правило**

Artifact является активом платформы.

Не результатом одноразовой операции.

**15. Artifact Discoverability**

Каждый Artifact должен быть пригоден для последующего обнаружения.

Платформа обязана обеспечивать возможность поиска и повторного использования Artifact.

**AD-001**

Artifact индексируется автоматически после создания.

**AD-002**

Artifact связывается с соответствующими Platform Objects.

**AD-003**

Artifact сохраняет сведения о происхождении.

**AD-004**

Artifact сохраняет сведения о связанных Workflow.

**AD-005**

Artifact должен быть доступен для поиска в пределах предоставленных полномочий.

**Архитектурное правило**

Необнаружимый Artifact не представляет ценности для платформы.

**16. Artifact Context**

Artifact существует в архитектурном контексте платформы.

Контекст определяет происхождение, назначение и область применения Artifact.

**CT-001**

Artifact связан с объектом, в результате обработки которого он был создан.

**CT-002**

Artifact связан с Execution Request, завершившим его создание.

**CT-003**

Artifact связан с соответствующим Workflow при его наличии.

**CT-004**

Artifact может быть связан с другими Artifact.

**CT-005**

Контекст Artifact является частью организационной памяти платформы.

**Архитектурное правило**

Ценность Artifact определяется не только его содержанием, но и его контекстом.

**17. Artifact Evolution**

Artifact развивается посредством последовательности изменений.

Развитие Artifact отражает развитие соответствующего бизнес-объекта.

**AE-001**

Каждое изменение приводит к созданию новой версии Artifact.

**AE-002**

История развития Artifact сохраняется полностью.

**AE-003**

Предыдущие версии остаются доступными для анализа.

**AE-004**

Связи Artifact сохраняются между всеми версиями.

**AE-005**

Эволюция Artifact является частью организационной памяти.

**Архитектурное правило**

Платформа хранит историю развития результатов деятельности, а не только их текущее состояние.

**18. Architecture Principles**

Artifact Architecture SSP основана на следующих принципах.

1.  Artifact является самостоятельным Platform Object.

2.  Artifact представляет результат завершённой деятельности.

3.  Representation не является Artifact.

4.  Physical Storage не является частью архитектурной модели.

5.  Artifact обладает собственной идентичностью.

6.  Artifact имеет независимый жизненный цикл.

7.  Artifact развивается посредством версий.

8.  Artifact существует в бизнес-контексте.

9.  Artifact предназначен для повторного использования.

10. Artifact является элементом организационной памяти платформы.
