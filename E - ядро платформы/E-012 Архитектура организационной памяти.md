**E-012 Архитектура организационной памяти**

**Версия:** 1.0

**Статус:** Draft

**Раздел:** E — Engineering Architecture

**1. Scope**

Настоящий документ определяет архитектурную модель Organizational Memory платформы Simple Solutions Practice.

Organizational Memory представляет собой систему накопления, сохранения и повторного использования опыта организации.

**2. Organizational Memory Principles**

Organizational Memory является самостоятельной архитектурной подсистемой платформы.

Её назначением является сохранение результатов деятельности организации независимо от участников, технологий и времени.

**MP-001**

Organizational Memory развивается непрерывно.

**MP-002**

Organizational Memory сохраняет опыт организации.

Не отдельных пользователей.

**MP-003**

Каждый новый Artifact может стать частью Organizational Memory.

**MP-004**

Организационная память используется при принятии новых решений.

**MP-005**

Повторное использование опыта является основной целью Organizational Memory.

**Архитектурное правило**

Платформа накапливает опыт.

Не документы.

**3. Memory Objects**

Organizational Memory состоит из Memory Objects.

Memory Object представляет собой архитектурную единицу накопленного опыта.

**MO-001**

Memory Object обладает собственной идентичностью.

**MO-002**

Memory Object может ссылаться на один или несколько Artifact.

**MO-003**

Memory Object может объединять несколько связанных результатов деятельности.

**MO-004**

Memory Object существует независимо от Workflow.

**MO-005**

Memory Object может использоваться повторно различными Cognitive Worker и Human Worker.

**Архитектурное правило**

Memory Object представляет накопленный опыт.

Не отдельный документ.

**4. Sources of Organizational Memory**

Источниками Organizational Memory являются:

- Artifact;

- Workflow;

- Business Decision;

- Platform Events;

- Business Rules;

- Human Experience;

- Cognitive Worker Experience;

- Historical Activity.

Все источники рассматриваются как равноправные элементы накопления опыта.

**Архитектурное правило**

Организационная память формируется всей деятельностью платформы.

**5. Memory Lifecycle**

Memory Object проходит последовательный жизненный цикл.

Жизненный цикл отражает накопление и использование организационного опыта.

**ML-001**

Memory Object создаётся после появления достаточного объёма связанного опыта.

**ML-002**

Memory Object может дополняться новыми связанными Artifact.

**ML-003**

Memory Object может уточняться по мере накопления опыта.

**ML-004**

Memory Object может использоваться неограниченное количество раз.

**ML-005**

Удаление Memory Object допускается только в соответствии с политикой хранения платформы.

**Архитектурное правило**

Организационная память развивается непрерывно.

**6. Memory Classification**

Каждый Memory Object относится к одной или нескольким категориям.

Классификация используется для поиска, анализа и повторного применения опыта.

**MC-001**

Memory Object классифицируется автоматически при создании.

**MC-002**

Классификация может уточняться по мере развития Memory Object.

**MC-003**

Memory Object может одновременно принадлежать нескольким категориям.

**MC-004**

Классификация является частью организационной памяти.

**MC-005**

Изменение классификации не изменяет идентичность Memory Object.

**Архитектурное правило**

Память должна быть структурирована.

Неупорядоченная память теряет ценность.

**7. Memory Retrieval**

Platform Kernel обеспечивает получение релевантного организационного опыта.

Поиск выполняется в пределах полномочий текущего Execution Context.

**MR-001**

Memory Object может использоваться Human Worker.

**MR-002**

Memory Object может использоваться Cognitive Worker.

**MR-003**

Memory Object может использоваться Platform Kernel при исполнении Workflow.

**MR-004**

Результаты поиска определяются релевантностью и контекстом.

**MR-005**

Получение организационного опыта не изменяет Memory Object.

**Архитектурное правило**

Организационная память предназначена для повторного использования.

**8. Memory Enrichment**

Организационная память может автоматически дополняться платформой.

Дополнение выполняется без изменения исходных Artifact.

**ME-001**

Новые Artifact могут расширять существующие Memory Object.

**ME-002**

Повторяющиеся решения могут формировать устойчивые шаблоны опыта.

**ME-003**

Platform Kernel может объединять связанные результаты деятельности.

**ME-004**

Обогащение Organizational Memory выполняется постепенно.

**ME-005**

Исходные результаты деятельности остаются неизменяемыми.

**Архитектурное правило**

Память развивается посредством накопления опыта.

Не посредством изменения истории.

**9. Organizational Experience**

Organizational Memory предназначена для накопления и повторного использования опыта организации.

Платформа рассматривает опыт как один из наиболее ценных корпоративных активов.

**OE-001**

Organizational Memory хранит результаты деятельности, их контекст и последствия принятых решений.

**OE-002**

Organizational Memory не является архивом документов.

**OE-003**

Organizational Memory не является базой знаний.

**OE-004**

Каждый Memory Object отражает завершённый фрагмент организационного опыта.

**OE-005**

Основной целью Organizational Memory является повышение качества последующих решений.

**Архитектурное правило**

Organizational Memory отвечает не на вопрос:

**«Что известно организации?»**

а на вопрос:

**«Что организация уже делала, при каких условиях, с каким результатом и чему это её научило?»**

**10. Memory Value**

Ценность Organizational Memory определяется возможностью повторного использования накопленного опыта.

**MV-001**

Memory Object должен быть пригоден для анализа человеком.

**MV-002**

Memory Object должен быть пригоден для обработки Cognitive Worker.

**MV-003**

Memory Object должен сохранять связь с исходными Artifact и Business Objects.

**MV-004**

Memory Object должен содержать достаточный контекст для интерпретации накопленного опыта.

**MV-005**

Каждое повторное использование Organizational Memory увеличивает её ценность.

**Архитектурное правило**

Организационная память существует не для хранения прошлого.

Она существует для повышения качества будущих решений.

**11. Memory Assisted Decisions**

Platform Kernel, Human Worker и Cognitive Worker могут использовать Organizational Memory при принятии решений.

Использование Organizational Memory носит рекомендательный характер и не подменяет архитектурные правила платформы.

**MD-001**

Organizational Memory используется для поиска аналогичных ситуаций.

**MD-002**

Organizational Memory используется для выявления успешных практик.

**MD-003**

Organizational Memory используется для выявления ранее допущенных ошибок.

**MD-004**

Organizational Memory используется для формирования рекомендаций.

**MD-005**

Окончательное решение всегда принимается в рамках текущего Execution Context с использованием действующих Business Rules, Policy и Platform Kernel.

**Архитектурное правило**

Прошлый опыт помогает принимать решения.

Он никогда не изменяет правила исполнения платформы.

**12. Organizational Learning**

Organizational Memory обеспечивает накопление как успешного, так и неуспешного опыта организации.

Каждый завершённый результат деятельности рассматривается как потенциальный источник обучения.

**OL-001**

Успешные результаты сохраняются как подтверждённые практики.

**OL-002**

Неуспешные результаты сохраняются как организационный опыт.

**OL-003**

Отклонённые решения могут представлять самостоятельную ценность.

**OL-004**

Причины принятия решений являются частью Organizational Memory.

**OL-005**

Отсутствие ожидаемого результата также рассматривается как накопленный опыт.

**Архитектурное правило**

Организация обучается на всей своей деятельности.

Не только на успешных результатах.

**13. Decision Context**

Каждое значимое решение должно сохраняться вместе с контекстом его принятия.

Контекст позволяет интерпретировать накопленный опыт при последующем использовании.

**DC-001**

Decision Context включает исходные условия принятия решения.

**DC-002**

Decision Context включает рассмотренные альтернативы при их наличии.

**DC-003**

Decision Context включает обоснование выбранного решения.

**DC-004**

Decision Context может включать выявленные риски и ограничения.

**DC-005**

Decision Context сохраняется совместно с соответствующим Memory Object.

**Архитектурное правило**

Организационная память хранит не только решение.

Она хранит причины его принятия.

**14. Experience Patterns**

Platform Kernel может выявлять повторяющиеся организационные практики.

Выявленные закономерности рассматриваются как Experience Patterns.

**EP-001**

Experience Pattern формируется на основании нескольких Memory Object.

**EP-002**

Experience Pattern отражает повторяющуюся организационную практику.

**EP-003**

Experience Pattern не изменяет исходные Memory Object.

**EP-004**

Experience Pattern может использоваться Human Worker и Cognitive Worker.

**EP-005**

Experience Pattern может уточняться по мере накопления нового опыта.

**Архитектурное правило**

Закономерности выводятся из опыта.

Они не заменяют сам опыт.

**15. Organizational Intelligence**

Organizational Memory является основой формирования Organizational Intelligence платформы.

Organizational Intelligence представляет собой способность платформы использовать накопленный опыт для поддержки последующих решений.

**OI-001**

Organizational Intelligence основывается исключительно на накопленном организационном опыте.

**OI-002**

Organizational Intelligence не изменяет Business Rules и архитектурные Policy.

**OI-003**

Organizational Intelligence формирует рекомендации, а не обязательные решения.

**OI-004**

Каждая рекомендация должна быть объяснима посредством соответствующих Memory Object.

**OI-005**

Использование Organizational Intelligence не освобождает участников процесса от ответственности за принимаемые решения.

**Архитектурное правило**

Платформа помогает принимать более качественные решения.

Окончательное решение всегда остаётся за исполнителем, ответственным за текущий Execution Context.

**16. Memory Confidence**

Каждый Memory Object обладает уровнем доверия (Memory Confidence).

Уровень доверия отражает степень надёжности накопленного организационного опыта.

**CF-001**

Memory Confidence определяется на основании подтверждённого опыта использования.

**CF-002**

Уровень доверия может изменяться по мере накопления нового опыта.

**CF-003**

Memory Confidence относится к Memory Object, а не к отдельному Artifact.

**CF-004**

Platform Kernel использует Memory Confidence при формировании рекомендаций.

**CF-005**

Уровень доверия не изменяет исходную историю организационного опыта.

**Архитектурное правило**

Организационная память хранит весь опыт.

Доверие определяет степень его применения.

**17. Organizational Validation**

Организационный опыт подтверждается практикой его повторного применения.

**OV-001**

Повторное успешное использование повышает уровень доверия.

**OV-002**

Выявленные ограничения уточняют область применимости опыта.

**OV-003**

Противоречивый опыт не удаляется из Organizational Memory.

**OV-004**

Platform Kernel сохраняет историю изменения уровня доверия.

**OV-005**

Организационная память отражает развитие опыта организации во времени.

**Архитектурное правило**

Опыт развивается.

История не переписывается.

**18. Explainable Recommendations**

Все рекомендации, сформированные на основании Organizational Memory, должны быть объяснимыми.

Пользователь должен иметь возможность проследить происхождение каждой рекомендации.

**ER-001**

Каждая рекомендация содержит ссылки на использованные Memory Object.

**ER-002**

Каждая рекомендация содержит обоснование своей применимости.

**ER-003**

Рекомендация не может ссылаться на недоступный организационный опыт.

**ER-004**

Platform Kernel фиксирует основания формирования рекомендации.

**ER-005**

Пользователь имеет возможность ознакомиться с использованным организационным опытом в пределах предоставленных полномочий.

**Архитектурное правило**

Каждая рекомендация должна быть проверяемой.

**19. Organizational Memory Principles**

Organizational Memory SSP основана на следующих принципах.

1.  Организационная память является самостоятельной архитектурной подсистемой.

2.  Организационная память хранит опыт, а не документы.

3.  Memory Object является единицей накопленного опыта.

4.  Artifact является источником организационной памяти.

5.  Организационная память развивается непрерывно.

6.  Повторное использование опыта увеличивает его ценность.

7.  История организационного опыта является неизменяемой.

8.  Доверие формируется практикой применения, а не субъективной оценкой.

9.  Все рекомендации должны быть объяснимыми и проверяемыми.

10. Organizational Memory поддерживает принятие решений, но не заменяет Platform Kernel.
