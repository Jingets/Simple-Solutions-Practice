**Business Object Model (BOM)**

**Назначение**

Business Object Model определяет состав бизнес-сущностей цифровой платформы Simple Solutions Practice, их жизненный цикл и взаимосвязи.

Данная модель является единственным источником описания бизнес-логики платформы и служит основой для разработки базы данных, API, автоматизации, пользовательских интерфейсов и технического задания.

На любом этапе используются связанные сущности:

- Document

- Payment

- Event

- Notification

- Workspace

**1. Partner**

Организация или физическое лицо, инициирующее сотрудничество.

**Атрибуты**

- ID

- тип

- наименование

- реквизиты

- ИНН (при наличии)

- контактные данные

- статус

**Связи**

Один Partner может иметь:

- несколько Contact;

- несколько Inquiry;

- несколько Project;

- общую историю сотрудничества.

**2. Contact**

Контактное лицо партнёра.

Именно Contact взаимодействует с платформой.

**Атрибуты**

- ФИО

- должность

- телефон

- e-mail

- предпочитаемый канал связи

- уровень доступа

**3. Inquiry**

Первичное обращение.

Является первой бизнес-сущностью платформы.

**Статусы**

- Новое

- Принято

- Назначен разговор

- Обсуждение

- Ожидание информации

- Закрыто

- Отказ

**Результат**

После завершения Inquiry назначается Discovery Meeting либо обращение закрывается.

**4. Discovery Meeting**

Профессиональный разговор.

Обязательный этап перед началом любого сотрудничества.

**Содержит**

- участников

- описание ситуации

- предварительную оценку

- рекомендации

- принятое решение

**Возможные решения**

- подготовить Proposal;

- запросить дополнительную информацию;

- рекомендовать иной формат помощи;

- отказаться от сотрудничества.

**5. Proposal**

Персональное предложение.

Формируется по результатам разговора.

**Содержит**

- цель проекта;

- ожидаемый результат;

- формат сотрудничества;

- стоимость;

- сроки;

- ограничения;

- срок действия.

**Статусы**

- Подготовлено

- Отправлено

- На согласовании

- Принято

- Отклонено

- Истекло

**6. Agreement**

Соглашение о начале сотрудничества.

Agreement фиксирует достижение взаимной договорённости.

Именно Agreement является точкой перехода от переговоров к реализации проекта.

**Формируется после**

- согласования Proposal;

- подтверждения обеими сторонами условий сотрудничества.

**Последствия создания Agreement**

Система автоматически:

- формирует договор-оферту;

- открывает Workspace;

- создаёт Project;

- формирует счёт;

- активирует процессы автоматизации;

- начинает жизненный цикл проекта.

**7. Cooperation Format**

Формат сотрудничества.

Определяет метод реализации проекта.

В системе используются следующие форматы:

- Экспертный взгляд

- Диагностика

- Совместная реализация

- Стратегическое сопровождение

Каждый формат определяет:

- этапы проекта;

- шаблоны документов;

- финансовую модель;

- правила завершения.

**8. Project**

Основная рабочая сущность платформы.

Создаётся автоматически после появления Agreement.

**Атрибуты**

- номер проекта;

- партнёр;

- формат сотрудничества;

- консультант;

- даты;

- статус.

**Статусы**

- Подготовка

- Ожидает оплаты

- Активный

- Приостановлен

- Завершён

- Архив

**9. Project Stage**

Отдельный этап проекта.

Позволяет отображать ход реализации независимо от выбранного формата сотрудничества.

**Атрибуты**

- название;

- описание;

- статус;

- плановая дата;

- фактическая дата.

**10. Deliverable**

Результат проекта.

Главный объект ценности.

В зависимости от формата сотрудничества Deliverable может представлять собой:

- экспертное заключение;

- диагностический отчёт;

- дорожную карту изменений;

- внедрённую систему;

- рекомендации;

- иной согласованный результат.

Каждый Deliverable имеет собственную версию и связан с конкретным Project.

**11. Document**

Любой документ платформы.

**Типы**

- Proposal

- Agreement

- Оферта

- NDA

- Счёт

- Дополнительное соглашение

- Акт

- Отчёт

- Приложение

Каждый документ имеет:

- версию;

- дату создания;

- автора;

- статус;

- историю изменений.

**12. Payment**

Платёж по проекту.

**Атрибуты**

- сумма;

- назначение;

- способ оплаты;

- дата;

- статус.

**Статусы**

- Ожидается

- Получен

- Частично получен

- Отменён

- Возвращён

Получение Payment автоматически инициирует следующий этап проекта.

**13. Event**

Системное событие.

Любое изменение состояния объекта создаёт Event.

Например:

- создан Inquiry;

- проведён Discovery Meeting;

- согласован Proposal;

- создан Agreement;

- получен Payment;

- завершён Stage;

- создан Deliverable.

Event является основой автоматизации платформы.

**14. Notification**

Автоматическое уведомление.

Создаётся системой при наступлении определённых Event.

Каналы доставки:

- e-mail;

- Telegram;

- MAX;

- внутренняя система уведомлений.

**15. Workspace**

Единое цифровое пространство проекта.

Создаётся автоматически после появления Agreement.

Workspace предоставляет участникам проекта доступ к:

- статусу проекта;

- этапам;

- документам;

- Deliverable;

- истории событий;

- платежам;

- переписке;

- уведомлениям.

Workspace не хранит собственных данных.

Он является единым интерфейсом ко всем связанным бизнес-сущностям.

**Архитектурные принципы**

**Единственный источник истины**

Каждая бизнес-сущность создаётся один раз и существует в единственном экземпляре.

**Событийная модель**

Любое изменение фиксируется как Event и становится доступным всем связанным процессам платформы.

**Автоматизация без дублирования**

Данные вводятся единожды и повторно используются всеми документами, сервисами и интерфейсами.

**Разделение этапов**

Платформа всегда различает четыре независимых состояния взаимодействия:

1.  Обсуждаем ситуацию.

2.  Формируем предложение.

3.  Достигаем соглашения.

4.  Реализуем проект.

Переход между состояниями возможен только после выполнения условий предыдущего этапа.

**Назначение модели**

Business Object Model является фундаментом цифровой платформы Simple Solutions Practice.

Любая новая функция, модуль или интеграция должны использовать существующие бизнес-сущности и не создавать альтернативных источников данных или параллельных бизнес-процессов.
